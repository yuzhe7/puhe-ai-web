## 一、赛道要求速读（决定改造方向的硬约束）

| 维度 | 官方要求 | 对本项目的直接影响 |
|---|---|---|

| 创新性 25% | 选题创新 10% / 技术方案创新 8% / 交互模式创新 7% | 保留项目书原创「双侧三层图谱 + 三维递进诊断」，新增「生成式 UI + Agent 思考可视化」交互创新 |

| 用户体验 10% | **流式输出渲染、AI 思考状态可视化、错误边界处理** 单列 3% | Copilot 必须真实流式 + 步骤可视化 + 上游异常降级 |
| 实用/社会价值 20% | 真实场景、问题解决、社会意义与商业潜力 | 项目书已有政策依据、试点验证、定价模式，可直接复用为答辩素材 |

### 评分权重的战略结论
> **AI 技术深度 35% + 创新性 25% = 60%**。项目书里最"值钱"的不是爬虫和 Neo4j，而是
> ①双侧三层知识图谱的原创架构、②跨域语义对齐、③三维递进式诊断、④PDCA 闭环。
> 改造思路：**保留这四个原创内核作为"选题/方案创新"的证据，把实现方式从"重后端"换成"AI Native 前端 + 轻量确定性算法 + 多 Agent 编排"**。

### 2.2 四个核心痛点 → 产品功能映射
| 项目书痛点 | 层级 | 本作品对应功能 | 所在页面 |
|---|---|---|---|
| 专业布局同质化 | 宏观 | Jaccard + 知识点重叠 + 图拓扑相似度热力图、TOP 风险清单、两两对比 | `/diagnosis?tab=macro` |
| 培养目标与需求脱节 | 中观 | 工程教育认证 12 项毕业要求雷达图、四态偏差矩阵与修订建议 | `/diagnosis?tab=meso` |
| 课程优化缺乏精准依据 | 微观 | 知识点↔技能跨域语义对齐、应加强/应新增/可精简指令、桑基流向图 | `/diagnosis?tab=micro` |
| 需求信息碎片化 | 数据底座 | 多模态文档接入 → 自动切片 → 端侧向量检索 → 强制证据引用 | `/data`、`/copilot` |

### 2.3 「双侧三层」本体 → 前端图谱模块
- 双侧：高校供给侧（专业 / 课程 / 培养目标 / 知识点，蓝）↔ 产业需求侧（岗位类别 / 岗位 / 能力要求 / 技能，橙）
- 三层：宏观 专业—课程｜中观 目标—能力｜微观 知识点—技能
- 前端实现：ECharts force 力导向图，支持层级切换、双侧开关、聚焦专业、节点搜索、点击展开属性、跨侧对齐连线（橙色）
- 生产可替换：同一 `buildGraph()` 接口换成 Neo4j Cypher 查询结果，前端零改动

### 2.4 「三维分析引擎」算法 → 确定性计算模块（`src/lib/graph.ts`）
| 维度 | 项目书公式 | 本作品实现 |
|---|---|---|
| 宏观 | S(A,B)=0.3×J(A,B)+0.4×K(A,B)+0.3×G(A,B) | `jaccard()` / `knowledgeOverlap()` / `topologySimilarity()`（课程类别 + 知识点共现向量的余弦，替代 Node2Vec，前端可实时算） |
| 中观 | SentenceBERT + Sinkhorn 最优传输，四态判定 | 以工程教育认证 12 项词表为统一维度，`gap = 产业需求度 − 校内覆盖度`，四态阈值 ±20 / ±10 |
| 微观 | 细粒度语义匹配 + 需求频次 → 三级标签 | `alignScore()`（别名精确命中 + 字符二元组余弦 + 5 条领域规则），输出应加强 / 应新增 / 可精简 / 保持 |

> **关键工程决策**：所有数字由本地确定性算法产出，大模型**只做语言组织，不产生数值**。
> 这同时满足「AI 安全与可控性 4%」「可解释性」「结果可复现」三项要求，也让无密钥演示成为可能。

### 2.5 项目书「四大创新点」→ 赛道「创新性 25%」申报口径
1. 双侧三层异构图谱 → **选题创新**：首次把分析粒度从"专业级"下沉到"知识点—技能级"（项目书称粒度细化 ≥20 倍）
2. 跨域语义对齐 → **技术方案创新**：教育话语 vs 产业话语的等价映射（"掌握面向对象程序设计方法" ≈ "熟练用 Java 做面向对象开发"）
3. 三维递进式诊断 → **技术方案创新**：市面产品只做单层，本作品贯通"战略层 → 执行层"
4. PDCA 数据驱动闭环 → **应用创新**：Collect → Analyze → Suggest → Track，月度/季度敏捷课程治理
5. **新增（本作品原创）交互创新**：生成式 UI 卡片 + Agent 思考过程可视化 + 证据溯源侧栏 + 语音提问/朗读

## 三、技术改造清单（原方案 → 参赛方案）

| 项目书原选型 | 参赛改造 | 理由 |
|---|---|---|
| Vue3 + Element Plus | **React 18 + Next.js 14 App Router + TypeScript + Tailwind CSS** | 赛道推荐首选；TypeScript 明确计分；API Routes 可做密钥隔离的 AI 接入层 |

| Chinese-BERT-wwm / SentenceBERT 微调 | **端侧 TF-IDF 稀疏向量 + 跨域术语词典 + 字符二元组余弦** | 浏览器/服务端零依赖可运行；体现「端侧 AI / 端云协同」前瞻方向；结果可复现 |
| ECharts + vis.js | **ECharts（动态导入）** | 保留项目书技术延续性，热力图/雷达/桑基/力导向图谱全覆盖，代码分割优化首屏 |
| 无 AI 对话 | **多 Agent + RAG + Function Calling + MCP + SSE 流式 + 多模态** | 直接对应 AI 深度 35% 的六个子项 |
| 无安全设计 | **注入拦截 / PII 脱敏 / 数值溯源 / 置信度 / 无密钥兜底** | 对应 AI 安全 4%，且是产品化必备 |
| Docker + Nginx | **Vercel / Next start 一键部署 + 公网在线演示** | 对应「在线演示（可选加分项）」 |

## 四、作品功能架构（6 个页面）

```
/              总览驾驶舱：平台价值、核心指标、三维引擎入口、AI 能力矩阵、运行状态
/graph         双侧三层知识图谱：层级/侧别切换、节点搜索、力导向交互、属性详情
/diagnosis     三维诊断工作台：宏观热力图+对比、中观雷达+偏差清单、微观指令+桑基
/copilot       AI 诊断 Copilot：多 Agent 流式对话、执行轨迹、生成式 UI、证据溯源、语音
/data          数据与知识库：多模态上传（TXT/DOCX/PDF/图片）、RAG 检索验证、质量看板、MCP 文档
/report        报告中心：按角色生成结构化诊断报告、打印导出 PDF、复制 Markdown
```

### AI 能力层（`src/lib/ai/`）
- `llm.ts`：OpenAI 兼容 SSE 流式 + 多轮 Function Calling + 视觉模型；无密钥自动降级
- `local-agent.ts`：本地确定性 Agent，真实执行规划/RAG/工具/安全/流式，仅语言组织用模板
- `tools.ts`：7 个工具注册表（RAG 检索、图谱查询、宏观/中观/微观诊断、岗位画像、报告生成）
- `prompts.ts`：系统提示词 + 五智能体角色 + Few-shot 规划样例 + 证据强制注入
- `safety.ts`：注入检测、PII 脱敏、输出数值溯源、置信度、兜底话术

### MCP 端点
`POST /api/mcp` 支持 `initialize` / `tools/list` / `tools/call` / `resources/list` / `resources/read`，
外部 Agent（Cursor、Claude Desktop、自定义智能体）可直接调用三维诊断能力，对应「MCP/工具集成 4%」。
