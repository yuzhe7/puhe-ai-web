## 二、三大新增功能

### 2.1 培养方案改革沙盘（What-if Simulation）

- **入口**：`/simulate`；**API**：`GET/POST /api/simulate`、`POST /api/syllabus`
- **算法内核**：`src/lib/simulator.ts`

**输入动作空间**
1. 任一课程学时在 24–96h 间调整（步进 8h）
2. 勾选/取消产业技能模块（按岗位 JD 需求强度排序，每模块 16h）
3. 精简 / 移除某门课程（可一键恢复）

**指标口径（全部确定性）**

| 指标 | 公式 / 依据 |
|---|---|
| 岗位匹配度 | `Σ(max_k[alignScore(kp_k, skill_i) × (0.35 + 0.65×coverage_k)] × demand_i) / Σ demand_i × 100`；`coverage = clamp(kp.hours × (newHours/baseHours) / 10, 0, 1)`；新增模块命中技能时取 0.96 |
| 毕业要求均衡度 | `100 − avg(|industryWeight − schoolWeight|)`，新增模块对「使用现代工具 / 项目管理 / 沟通 / 团队」产生有上限的增益 |
| 现代工具覆盖 | 13 个高需求现代技能（Git/CI、Docker、LLM/RAG、模型部署、Spark/Flink…）按需求强度加权的覆盖率 |
| 实践学时占比 | `(实践/拓展课程学时 + 新增模块学时) / 总学时 × 100` |
| 待调整知识点 | 高需求低覆盖 + 衰退型知识点 + 岗位技能中仍无覆盖的「应新增」项 |

**自动寻优**：`autoOptimize()` 在「新增模块 / 加 8 学时 / 减 8 学时」候选动作空间内，按
`单位学时增益 = Δ匹配度 / 成本` 贪心择优，受 `总学时 ≤ 基线 + 预算` 约束，最多 6 轮，输出完整决策轨迹。
这是可解释的组合优化，不是大模型"拍脑袋"给方案。

**实测样例**（计算机科学与技术 → AI应用开发工程师，预算 +48h）：

```
现行匹配度 49.1 → 寻优后 78.8；总学时 720 → 768；新增 3 个模块；搜索 4 轮收敛
第 1 轮：新增产业模块「Python」  +11.6（单位学时增益 0.73）
第 2 轮：新增产业模块「模型微调与部署」 +9.9（0.62）
第 3 轮：新增产业模块「AI伦理与合规」 +8.2（0.51）
第 4 轮：候选动作均无正增益，搜索收敛
```

**衍生交付**：一键生成改革后《课程教学大纲》Markdown（课程目标 / 学时分配表 / 跨域术语对齐 / 考核方式 / 证据来源），可下载 `.md`；整套方案可导出 JSON。

### 2.2 岗位能力路径规划（学生视角）

- **入口**：`/path`（支持 `?job=` 深链接）；**API**：`GET/POST /api/path`
- **算法内核**：`src/lib/pathway.ts`

**图构建**
- 节点：专业范围内全部知识点 `k:*` + 目标岗位技能 `s:*`
- 边 ①：同课程知识点共现（权 0.42，双向）
- 边 ②：跨课程语义邻接（`alignScore ≥ 0.32`，权 `max(0.3, 1.1 − score)`），避免图谱被课程割裂
- 边 ③：每个技能保留对齐度最高的 3 条知识点入边（权 `max(0.15, 1 − score)`），保证全新产业术语也可达

**求解**：多源 Dijkstra（起点 = 学生已掌握知识点；未提供时取前 4 个基础知识点），
输出每个目标技能的最小学习成本链、置信度 `92 − cost×26`、就绪度（按需求强度加权）；
再按课程类别先修顺序把待补知识点排入 **每学期 96h 预算** 的分学期计划，无对应知识点的技能自动转为校企共建产业实训模块。
页面以环形进度条、力导向补强子图、可展开技能路径链、三学期计划卡呈现，支持导出学习计划 Markdown。

**实测样例**（AI应用开发工程师 / 计算机科学与技术 / 已掌握 3 个知识点）：
`就绪度 6% · 预计 104h · 2 个学期 · 17 节点 / 17 条路径边`，低对齐技能（如 Python）给出低置信"需新建模块"链路而非伪造路径。

### 2.3 Deep Research 多智能体研究工作台

- **入口**：`/research`；**API**：`POST /api/research`（SSE）
- **算法内核**：`src/lib/ai/research.ts`

**执行链路（全部真实执行，非动画模拟）**
1. `规划智能体`：把问题拆成 4 个可独立取证的子问题（自动识别专业 / 课程 / 岗位实体）
2. `检索智能体`：每个子问题独立调用 `retrieve()` 做 RAG 多路召回（带跨域术语扩展）
3. `对齐智能体`：每个子问题调用一个确定性工具（`analyze_similarity` / `diagnose_competency` / `locate_knowledge_gap` / `profile_job` 或 `generate_report`）
4. `交叉验证`：按 `source` 去重、统计独立证据源、计算综合置信度
5. `报告智能体`：输出带 `[n]` 引用的研究简报；配置 `AI_API_KEY` 时用 `llmComplete()` 做**证据约束下的语言组织**，失败自动回退确定性模板

**SSE 事件协议**（自定义、与 `/api/chat` 解耦）：
`phase` / `plan` / `evidence` / `tool` / `finding` / `crosscheck` / `delta` / `done` / `error`

**实测**：一次研究产生 **90 个 SSE 事件**
（`phase×7 · plan×1 · evidence×4 · tool×4 · finding×4 · crosscheck×1 · delta×68 · done×1`），
简报可导出带参考证据清单的 Markdown。
