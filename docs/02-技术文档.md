# 1. 项目概述

## 1.1 项目定位

「谱合产教」是连接高校人才培养体系与产业人才需求体系的数字桥梁。名称寓意：「谱」= 知识图谱技术底座，
「合」= 教育供给与产业需求融合，「产教」= 产教融合国家战略。本作品将高校静态的培养方案与课程大纲，
与产业动态、碎片化的岗位技能需求，在「专业 — 培养目标 — 知识点」的微观粒度上系统性对齐与量化分析，
把专业建设决策从依赖定性经验判断，转变为以数据和证据为支撑的精准决策。

## 1.2 从大创项目到 AI Native Web 作品

原始项目书为《中国国际大学生创新大赛（2026）》参赛的商业计划书，设计了一套
Scrapy 爬虫 + Neo4j + PostgreSQL + MongoDB + FastAPI + Vue3 的重后端大数据平台。
传智杯 AI WEB 赛道明确要求「以前端 Web 应用为主要呈现形态，后端服务仅作为 AI 能力的接入层，
不作为重点考察对象」，并把「AI 技术深度」设为 35% 的最高权重。因此本作品：

- **保留**原创的四个内核：双侧三层图谱架构、跨域语义对齐、三维递进式诊断、PDCA 闭环；
- **替换**实现路径：重后端 → AI Native 前端 + 端侧确定性算法 + 多智能体编排；
- **新增**赛道要求的六项 AI 能力：LLM、Agent、RAG、多模态、AI 安全、MCP/Function Calling。

## 1.3 演示数据范围

以河北水利电力学院为试点场景：37 个本科专业（本演示集抽取 12 个代表性专业）、
41 门课程、90+ 知识点、12 类岗位、38 个技能标签、工程教育认证 12 项毕业要求、
5 份政策/术语语料，共构建约 200 个 RAG 知识切片。产业岗位需求样本合计 10,070 条。
**全部为团队自建教学演示数据，不含任何真实学生个人信息。**

> **当前口径（v10，2026-11-16）**：62 专业 / 109 课程 / 334 知识点 / 38 岗位 / 84 技能 / 28,640 条 JD 样本；
> 页面 14 个、API 18 个、MCP 工具 10 个。
> 本节数据为 v1 的**试点校抽样集**（12 个专业），与 v3 起的「全国学科目录观察池」是两套口径，
> 分层说明见 `docs/11` 第 6 节；两者不矛盾，也不可相互替代。

# 2. 需求分析与问题定义

## 2.1 政策与场景依据

《教育强国建设规划纲要（2024—2035 年）》要求深化产教融合、科教融汇，推动高校人才培养与
国家战略、产业需求精准对接；新一轮本科教育教学审核评估把「专业设置与社会需求适应度」列为核心指标；
工程教育认证以 12 项毕业要求约束培养质量。高校亟需可量化、可追溯、可动态更新的专业建设证据链。

## 2.2 四大核心痛点

| 编号 | 痛点 | 层次 | 传统做法 | 局限 |
|---|---|---|---|---|
| P1 | 专业布局同质化 | 宏观结构 | 专家评审、人工比对课程表 | 主观、周期 3-5 年、无法发现"课名不同但知识点重叠" |
| P2 | 培养目标与需求脱节 | 中观标准 | 定期修订培养方案 | 教育话语与产业话语不互通，缺乏自动化偏差诊断 |
| P3 | 课程优化缺乏精准依据 | 微观执行 | 教师凭经验增删内容 | 无法定位到具体知识点的新旧与强弱 |
| P4 | 需求信息碎片化 | 数据基础 | 人工整理招聘信息 | 非结构化、表述各异、无法关联到课程体系 |

四者呈递进关系：P1 限制差异化 → P2 导致方向不明 → P3 使执行无据 → P4 加剧信息割裂，
是系统性问题，需要贯通宏观、中观、微观并连接两侧的一体化方案。

## 2.3 用户角色（RBAC 视角）

| 角色 | 核心诉求 | 对应功能 |
|---|---|---|
| 系统管理员 | 数据源配置、质量监控 | 数据管理、多模态接入、质量看板 |
| 教育管理者 | 专业审批、区域布局决策 | 宏观热力图、决策简报 |
| 院系负责人 | 培养方案修订、专业建设 | 中观偏差矩阵、专业诊断报告 |
| 课程负责人 | 课程大纲修订 | 微观知识点缺口清单 |
| 学生 | 职业规划、选课 | 技能画像、岗位匹配、学习路径 |

## 2.4 功能性需求与非功能性需求

- FR1 双侧三层图谱可视化：层级切换、侧别开关、节点搜索、属性查看、跨侧对齐连线
- FR2 三维诊断：宏观相似度、中观能力偏差、微观知识点缺口，结果可复算
- FR3 AI 对话：流式输出、Agent 步骤可视化、工具调用、生成式 UI、证据引用
- FR4 知识库：多模态文档接入、自动切片、实时检索
- FR5 报告：按角色生成、打印/导出 PDF、Markdown 复制
- NFR1 零密钥可运行：无外部依赖、断网可用
- NFR2 可复现：所有数值由确定性算法产出
- NFR3 安全：密钥隔离、注入拦截、PII 脱敏、输出溯源
- NFR4 性能：图表按需加载、首屏 JS 最小化、SSE 增量渲染

# 3. 系统总体架构设计

## 3.1 五层逻辑架构

```
应用层   /  /graph  /diagnosis  /copilot  /data  /report        （React 组件 + 生成式 UI）
AI 层    多 Agent 编排 · RAG · Function Calling · MCP · 安全网关  （src/lib/ai）
分析层   宏观 S(A,B) · 中观四态偏差 · 微观三级标签 · 跨域语义对齐 （src/lib/graph）
图谱层   双侧三层图谱构建（nodes / links / categories）           （buildGraph）
数据层   专业/课程/知识点/岗位/技能/能力/政策 + RAG 切片索引      （src/lib/dataset, rag）
```

## 3.2 双侧三层知识图谱本体

| 层级 | 高校供给侧节点 | 产业需求侧节点 | 核心关系 | 支撑分析 |
|---|---|---|---|---|
| 宏观 | 专业、课程 | 岗位类别、岗位 | 包含、前修、归属、产教对齐 | 专业相似度、同质化 |
| 中观 | 培养目标、毕业要求、能力 | 岗位、岗位能力要求 | 支撑、要求、语义对齐、能力缺失 | 培养目标偏差诊断 |
| 微观 | 课程、知识点、教学环节 | 技能、工具要求 | 包含知识点、强匹配、语义对齐 | 知识点缺口定位 |

三层之间通过共享实体节点与跨层关联边纵向贯通，双侧之间通过跨域语义对齐关系横向连接。
本体共定义 7 类核心概念：专业、课程、培养目标、知识点、岗位、技能、能力要求。

## 3.3 前端工程架构

- **路由**：Next.js 14 App Router，6 个页面按业务域划分，天然代码分割
- **组件**：`AppShell`（导航/状态）、`ui.tsx`（Card / StatCard / Badge / Segmented / MarkdownLite / ProgressBar）、
  `EChart.tsx`（动态导入封装 + ResizeObserver）
- **状态**：页面级 React Hooks；跨页共享的运行状态通过 `/api/status` 拉取，避免全局状态污染
- **样式**：Tailwind CSS 3 + 自定义 CSS 变量，统一色板（高校侧 #3461F4 / 产业侧 #E8843C），响应式断点 sm/lg/xl
- **可视化**：`charts.ts` 为纯函数配置构造器（热力图 / 雷达 / 桑基 / 力导向图 / 条形），便于单测与复用

## 3.4 AI 接入层（唯一的服务端逻辑）

| 端点 | 职责 | 关键实现 |
|---|---|---|
| `POST /api/chat` | 多 Agent 流式对话 | SSE 事件协议 `step/tool/delta/card/citations/safety/done/error` |
| `POST /api/rag` | 检索验证 | 查询扩展 + Top-K 召回 |
| `POST /api/ingest` | 多模态接入 | TXT/DOCX/PDF/图片/粘贴文本 → 切片入库 |
| `POST /api/analyze` | 确定性分析 | 三维算法 + 图谱构建 |
| `POST /api/mcp` | MCP JSON-RPC | initialize / tools/list / tools/call / resources/* |
| `GET /api/status` | 运行态 | 模式、工具数、知识切片数 |

> 服务端代码总量刻意保持精简，符合官方「后端仅作 AI 能力接入层」的定位。

# 4. AI 技术方案

## 4.1 大模型选型理由

| 候选 | 优势 | 取舍 |
|---|---|---|
| OpenAI GPT-4o | 能力最强、生态成熟 | 费用高、国内访问不稳定 |
| Anthropic Claude | 长文本强 | 国内接入不便 |
| **DeepSeek / 智谱 GLM / 通义千问** | **OpenAI 兼容协议、中文强、成本低、GLM-4-Flash 有免费额度** | **选定为主接入** |
| 浏览器端 Transformers.js | 端侧隐私好、零成本 | 首包大、中文语义弱于云端模型 |

**最终策略：端云协同 + 协议抽象**。所有模型通过 OpenAI 兼容 `/chat/completions` 接入，
由 `AI_BASE_URL` / `AI_MODEL` / `AI_API_KEY` 三个环境变量切换，一套代码支持多家厂商；
语义向量化与检索完全在端侧完成，云端模型只做推理与语言组织，费用与延迟可控。

## 4.2 集成方式：SSE 流式 + Function Calling 多轮循环

`runLLMAgent()` 的编排流程：

1. **检索智能体**：先用 `retrieve(query, 5)` 召回证据，作为 `system` 消息强制注入上下文
2. **规划智能体**：System Prompt 含 7 条硬约束（禁止编造数字、必须引用证据、结论须可执行、无证据须拒答等）
3. **对齐智能体**：把 7 个工具以 OpenAI `tools` 参数传给模型，`tool_choice: auto`
4. **解析 SSE**：逐 `data:` 帧解析 `delta.content` 与增量 `tool_calls`（按 index 累积 `arguments`）
5. **工具执行**：`runTool(name, args)` 调用本地确定性算法，结果以 `role: tool` 回填，最多 4 轮
6. **报告智能体**：输出 `verifyGrounding()` 数值溯源校验后，逐 token 推送前端
7. **异常兜底**：上游超时/报错/无密钥 → 自动切换 `runLocalAgent()`，功能不中断

**流式协议**（前端按 `type` 分发渲染）：
```
step      智能体步骤（思考状态可视化）
tool      Function Calling 调用记录
delta     逐 token 文本
card      生成式 UI 结构化卡片
citations RAG 证据片段
safety    安全检查结果
done      完成（含运行模式）
error     错误边界
```

## 4.3 RAG 方案：端侧轻量向量检索

- **切分**：按中文句末标点分句，窗口 ≤200 字，保留 `source / sourceType / title` 元信息
- **向量化**：中文按字二元组（`bigram`）、英文按词，构建稀疏 TF 向量，乘 IDF 权重
- **查询扩展**：`expandQuery()` 用教育—产业术语词典把"HashMap / 哈希表"映射到"哈希与散列"，
  把"CI/CD / 流水线"映射到"持续集成"，解决跨域话语鸿沟
- **排序**：稀疏向量余弦相似度 + 标题命中加权 0.08，Top-K 过滤低分
- **增量入库**：`ingestDocument()` 支持用户上传文档实时切片加入索引，无需重建全库
- **证据约束**：召回片段注入 Prompt，前端渲染「证据溯源」侧栏；答案数值与证据不匹配时追加复核提示

> 该方案对应官方「鼓励探索浏览器端 AI 推理（Transformers.js / WebGPU），体现端侧智能的技术前瞻性」，
> 且比加载百 MB 级模型更适合高校评审环境：零依赖、零费用、100% 可复现。

## 4.4 多 Agent 工作流设计

| 智能体 | 输入 | 输出 | 可观测点 |
|---|---|---|---|
| 规划智能体 | 用户自然语言 | 工具链计划 | `step: 任务编排` |
| 检索智能体 | 查询 | Top-K 证据 | `citations` |
| 对齐智能体 | 工具名 + 参数 | 确定性计算结果 | `tool` + `card` |
| 诊断智能体 | 多工具结果 | 交叉校验结论 | `step: 交叉校验` |
| 报告智能体 | 结论 + 证据 | 流式文本 + 引用 | `delta` + `safety` |

**本地确定性引擎**并非"假聊天"：RAG、工具调用、算法、安全校验全部真实执行，
仅把"语言组织"用模板完成，保证在没有密钥的环境下也能展示完整的 AI 工作流。

## 4.5 MCP / Function Calling 工具集

7 个工具：`retrieve_knowledge` · `query_graph` · `analyze_similarity` · `diagnose_competency` ·
`locate_knowledge_gap` · `profile_job` · `generate_report`。

同一份 `tools` 注册表同时暴露给 LLM 的 `tools` 参数与 `/api/mcp` 的 `tools/list` / `tools/call`，
实现「一次定义、双协议复用」，外部 Agent（Cursor、Claude Desktop、自研智能体）可直接调用诊断能力。

## 4.6 多模态能力

| 模态 | 通道 | 实现 |
|---|---|---|
| 文本 | TXT / MD / CSV / JSON / 粘贴 | TextDecoder 直读 |
| 文档 | DOCX | `mammoth` 抽取正文 |
| 文档 | PDF | `unpdf` 抽取文本层（扫描件提示改用图片通道） |
| 图像 | PNG / JPG / WEBP | 转 dataURL → 视觉模型 `image_url` 抽取岗位技能 |
| 语音输入 | 麦克风 | Web Speech API `SpeechRecognition`（zh-CN） |
| 语音输出 | 扬声器 | `speechSynthesis` 朗读结论 |
| 视觉输出 | 图表 / 图谱 | ECharts 生成式 UI 卡片直接渲染在对话流中 |

## 4.7 AI 安全与可控性

1. **输入侧**：正则检测提示词注入（忽略指令 / DAN / 输出 system prompt 等），命中即 `block`；
   手机号、身份证、学号自动脱敏；输入超 1200 字截断
2. **输出侧**：`verifyGrounding()` 提取答案中的数值，与证据文本比对，≥4 处无法溯源即追加复核提示
3. **架构侧**：所有数值由确定性算法产出，模型不产生数字；Prompt 强制引用来源
4. **密钥侧**：`AI_API_KEY` 只在服务端进程环境，`fetch` 由 API Route 发起，浏览器只收到 SSE 文本
5. **兜底侧**：无密钥 / 上游 5xx / 超时 → 自动降级本地引擎；日志经 `sanitizeForLog()` 脱敏

## 4.8 优化策略

- **成本**：端侧承担检索与全部数值计算，云侧只做一次语言组织；Demo 模式零成本
- **延迟**：SSE 首 token 直达；工具结果并行可视化，用户不必等待完整回答
- **首屏**：ECharts `next/dynamic` + `ssr:false`，图表库不进入首屏 bundle；`lucide-react` 按需引入
- **稳定**：`AbortSignal.timeout(60s)`、`try/catch` 全链路、DeltaQueue 桥接避免背压
- **可复现**：算法纯函数 + 固定数据集，相同输入永远得到相同输出

# 5. 核心功能实现

## 5.1 宏观：专业同质化分析

```
J(A,B) = |A∩B| / |A∪B|                          课程集合 Jaccard
K(A,B) = |KA∩KB| / |KA∪KB|                      知识点集合重叠率
G(A,B) = cos(vA, vB)                            课程类别 + 知识点共现向量余弦
S(A,B) = 0.3·J + 0.4·K + 0.3·G                 综合评分，≥0.6 判高风险
```

`K` 能发现「课程名称不同但知识点高度重叠」的隐性同质化；`G` 以轻量图拓扑向量替代项目书的
Node2Vec 图嵌入，保留结构化信息的同时可在浏览器实时计算。试点对照：计算机科学与技术 vs 软件工程
课程 Jaccard 0.68、知识点重叠率 72.3%，与教师经验判断一致性 85%+。

## 5.2 中观：培养目标偏差诊断

以工程教育认证 12 项毕业要求为统一能力词表，`gap = 产业需求度 − 校内覆盖度`：

| 状态 | 判定 | 典型项 |
|---|---|---|
| 培养不足 | gap ≥ 20 | 使用现代工具、沟通、项目管理 |
| 部分匹配 | 10 ≤ gap < 20 | 设计/开发解决方案、个人和团队 |
| 高度匹配 | \|gap\| ≤ 10 | 问题分析、职业规范 |
| 过度培养 | gap ≤ −20 | 环境和可持续发展、终身学习 |

项目书的 SentenceBERT + Sinkhorn 最优传输多对多对齐，在演示版以「统一词表 + 语义对齐分数」
近似，保证可复现；生产版可替换回原算法，前端接口不变。

## 5.3 微观：知识点缺口定位

`alignScore(kp, aliases, skill)` 三层打分：
1. 别名精确命中 / 子串包含 → 0.94
2. 字符二元组余弦（别名 ×0.95，原名 ×0.6）
3. 5 条领域规则（面向对象↔Java、大模型↔LLM/RAG、软件测试↔CI、BIM/GIS↔数字孪生等）

结合产业需求强度与当前学时，输出四级指令：

| 指令 | 条件 | 输出 |
|---|---|---|
| 应加强 | 需求 ≥75 且覆盖不足，或需求高且趋势上升 | 增加课时 + 产业案例 + 实践环节 |
| 应新增 | 高需求技能在课程体系中完全无对应知识点 | 新增模块或融入现有章节 |
| 可精简 | 需求 ≤38（低频/衰退） | 压缩约 30% 学时 |
| 保持 | 供需基本平衡 | 维持并补充过程性评价 |

每条建议携带 `evidence`（匹配到的技能标签与对齐度），可直接用于课程大纲修订。

## 5.4 交互式知识图谱

ECharts `series.type = 'graph'` + `layout: 'force'`，节点按 6 类着色（蓝=高校侧 / 橙=产业侧），
跨侧对齐关系用橙色曲线并加 `curveness`。支持拖拽、缩放、点击展开属性、按名称/属性搜索、
层级与侧别动态重建。所有节点元数据来自 `meta` 字段，与算法共用一份数据源。

## 5.5 AI Copilot 交互

- 左侧对话流：逐 token 渲染（自研轻量 Markdown 渲染器，零依赖）、生成式 UI 卡片、朗读按钮

## 5.6 报告中心

# 10. v2 增补：决策智能、个体路径与主题工程（2026-11-04）

## 10.1 What-if 培养方案改革沙盘

- **输入动作空间**：`hours: Record<courseName, 24..96>`、`modules: skillName[]`（每模块 16 学时）、`removed: courseName[]`
- **教学覆盖系数**：`coverage(kp) = clamp(kp.hours × (newHours / baseHours) / 10, 0, 1)`
- **岗位匹配度**：`Σᵢ [maxₖ(alignScore(kpₖ, skillᵢ) × (0.35 + 0.65·coverageₖ)) × demandᵢ] / Σᵢ demandᵢ × 100`；模块命中技能取 0.96
- **其余四维**：毕业要求均衡度 `100 − avg(|industry − school|)`、13 项现代工具加权覆盖率、实践/拓展学时占比、待调整知识点数
- **自动寻优**：在 `{新增模块, +8h, −8h}` 候选空间内，按 `Δ匹配度 / 学时成本` 贪心择优，约束 `总学时 ≤ 基线 + 预算`，最多 6 轮，输出可解释决策轨迹；明确标注为**近似最优**而非全局最优
- **衍生**：`generateSyllabus()` 按知识点产业需求强度与改革后学时比例生成教学大纲（课程目标 / 学时表 / 术语对齐 / 考核 / 证据来源）

## 10.2 岗位能力补强路径（图算法）

- 节点：知识点 `k:*` 与岗位技能 `s:*`；边：同课程共现（0.42）、跨课程语义邻接（`alignScore≥0.32`，权 `max(0.3, 1.1−score)`）、每个技能 Top-3 知识点入边（权 `max(0.15, 1−score)`）
- 求解：**多源 Dijkstra**，起点为学生已掌握知识点；节点 <150，采用线性取最小值的 O(V²+E) 实现，零依赖
- 输出：每条技能的最小成本链、置信度 `92 − cost×26`、按需求强度加权的就绪度；不可达时输出低置信「需新建产业模块」兜底链，不伪造路径
- 排课：按课程类别先修顺序把待补知识点装入每学期 96h 预算，形成分学期计划

## 10.3 Deep Research 多智能体研究引擎

### 11.4 间接提示词注入防护

RAG 系统的特有风险是**文档投毒**：攻击者在上传文件中写入「忽略以上所有指令…」，切片入库后经检索注入
大模型上下文劫持 Agent。本项目采用三层防线：

1. **入库**：`ingestDocumentGuarded()` 按句调用 `hasInjection()`，丢弃可疑句并返回 `rejected` 计数；
   `/data` 页展示「AI 安全：已拦截 N 段疑似提示词注入内容」。
2. **检索**：`retrieve()` 对每个命中执行 `sanitizeUntrustedText()` 二次净化，指令片段替换为 `[已移除可疑指令]`。
3. **Prompt**：证据以 citation 形式注入并明确标注为不可信数据，配合 `guardInput()` 输入侧注入拦截与
   `verifyGrounding()` 输出侧数值溯源。

# 12. v4：魔搭 ModelScope 接入与创空间部署（2026-11-05）

### 12.1 可插拔服务商预设

项目没有自训模型：诊断数值由确定性算法给出，LLM 只负责语言组织与工具编排。
`src/lib/ai/providers.ts` 把 5 家 OpenAI 兼容服务商抽象为 `{ baseUrl, defaultModel, throttleProne }` 预设，
`getLlmConfig()` 按 `AI_PROVIDER → AI_BASE_URL/AI_MODEL 显式覆盖 → DeepSeek 默认` 的顺序解析，
并兼容魔搭官方命名的 `MODELSCOPE_SDK_TOKEN`。切换到魔搭只需：

```
AI_PROVIDER=modelscope
MODELSCOPE_SDK_TOKEN=ms-xxx     # https://modelscope.cn/my/myaccesstoken
```

即自动得到 `base_url=https://api-inference.modelscope.cn/v1`、`model=Qwen/Qwen3-Coder-30B-A3B-Instruct`。
代码还识别「旧模板残留」：若用户切到魔搭但没删掉 `.env.local` 里的 DeepSeek 默认值，会自动忽略，避免覆盖预设。

### 12.2 兼容性改造

| 问题 | 处理 |
|---|---|
| 免费推理动态限流 429 | `callLLM()` 对 `throttleProne` 服务商在「尚未读流」时退避重试 3 次，尊重 `Retry-After`（上限 8s）；仍失败由 SSE 泛化错误 + 本地引擎兜底 |
| 推理模型只返回 `delta.reasoning_content` | `readSSE()` 同时解析 `content` 与 `reasoning_content`，纯推理模型用思维链兜底答案，并把推理长度作为「推理智能体 · 思维链」步骤事件可视化 |
| 密钥外泄风险 | `/api/status` 只输出 `tokenConfigured` 布尔值与服务商元信息；`scripts/check-modelscope.mjs` 打印凭证时只显示 `ms-***xx` |
| 视觉模型误配 | `getVisionConfig()` 改为只有显式设置 `VISION_MODEL` 才启用，避免把文本模型 ID 打到 `image_url` 请求 |
| 无凭证 / 断网 | `DEMO_MODE=true` 或缺少 Token 时强制本地确定性引擎，9 页面与全部算法仍可演示 |

# 13. v10 增补：数值溯源、系统自检与 Agent 评测（2026-11-16）

本次迭代没有增加业务功能，主要处理两个问题：分数能不能被核实，诊断结论能不能落到教学文件上。全部实现在本地完成，没有引入新的运行时依赖。

## 13.1 数值溯源（`/api/trace` 与溯源抽屉）

此前页面上只显示最终分数，中间过程看不到。现在任一分数都可以展开，依次显示计算公式、逐步中间量和最终结果，末尾附一次独立复算：用另一条装配路径把同一个分数重算一遍，与正式接口值比对，不一致就标红。

三类对象的拆解方式如下。

| 对象 | 拆解内容 |
| --- | --- |
| 岗位契合度 | 逐个技能的对齐度与加权贡献、归一化过程、领域亲和度系数 |
| 同质化评分 | 课程 Jaccard、知识点重叠率、图拓扑余弦三个分量，附交集与并集规模 |
| 知识点缺口 | 各技能的加权合成过程，以及覆盖率与判定阈值 |

复算逻辑写在 `src/lib/trace.ts`，与正式计算共用底层原语，但装配方式独立。这样做的用意是：如果哪天正式计算的拼装出错，复算会先暴露出来。入口接在 `/majors` 的岗位分与同质化分数、`/diagnosis` 的综合评分上。抽屉支持 Esc 关闭，也可以把整条计算链复制成 JSON 存档。

## 13.2 系统自检（`/health` 与 `/api/selfcheck`）

自检页把 19 项断言分成三组，逐项显示实测值与耗时。

数据组检查五张主表的规模是否与版本一致，专业到课程、课程到知识点、岗位到技能这几层引用是否双向闭合，主键与名称有无重复。算法组检查相似度矩阵的规模是否为 n(n+1)/2、连续两次计算是否逐项相同、自比对结果是否为 1、是否存在非有限值；另有两项回归断言，一项确认泛化别名不会拿到过高的对齐分，一项确认领域闸门确实生效。运行组检查限流窗口、RAG 召回与导出文件的结构。

全部通过时接口返回 200，有失败项返回 503，验收脚本可以直接用状态码判断。

## 13.3 Agent 评测（`/eval` 与 `/api/eval`）

评测集有 28 条固定用例，分成检索、诊断、数值、安全、边界五类，全部离线执行，不消耗 token。

指标有四项。实体召回看回答是否覆盖提问涉及的实体；数值可溯源看回答里出现的每个数字能否在证据文本中找到，这一项参考了 ragas 中 Faithfulness 的做法，但用本地确定性算法实现，不调用评测模型；安全召回看注入类提问是否被拦截；最后一项是自检漏报，指 Agent 自己的 `verifyGrounding` 判定通过、而评测独立复算发现有未溯源数值的次数，越小越好。

为了让比对有意义，评测使用的证据与 Agent 内部保持同源：同一个清洗后的查询、同一次 `retrieve`、同一组工具参数重跑。两边结论不一致时，差异只可能来自校验逻辑本身。统计时把不一致分成漏报与误报两个方向，前者是危险方向，后者偏保守，分开记录。

## 13.4 交付物导出（`/api/export`）

诊断结论最终要交给教务使用，因此增加了 CSV 导出，采用 UTF-8 BOM 编码，Excel 与 WPS 可以直接打开。

导出内容有两种。课程—知识点矩阵共 18 列，包含课程名、课程类别、学分、现行学时、改革后学时、学时变化、知识点、Bloom 层次、产业需求强度、覆盖度、缺口判定、调整建议与对齐的产业技能；岗位技能对齐明细共 11 列，记录每项岗位技能对应的最相近知识点、对齐度与加权贡献。

在沙盘里调整过学时后，导出的即调整后的方案。为此 `knowledgeGaps` 增加了一个可选的 `hours` 参数，传入时按比例缩放各知识点学时，使覆盖率与判定随课时变化；不传时行为与之前一致。

## 13.5 同期修复的两个缺陷

岗位匹配的排序曾出现明显偏差，62 个专业里有 36 个的最高契合岗位落在同一个医疗岗上。排查后发现四处问题叠加：别名包含被硬编码为 0.94；对齐规则只要求两侧任意一词命中；完全同名反而只得到 0.6；以及缺少领域判断。修正后，最高契合岗位的分布扩散到 18 个。

Copilot 的流式接口在客户端断开时会抛出 `Invalid state: Controller is already closed`。原因是 `send` 直接调用 `controller.enqueue`，而异常处理里又调用了一次 `send`。现在改为软失败并停止后续生成，`close` 也加了保护。

## 13.6 当前规模

类型检查与 ESLint 均无告警，生产构建通过，共 14 个页面与 18 个 API，首屏共享 JS 仍为 87.3 kB。脚本断言方面，`verify:majors` 44 项、`verify:links` 68 项、`verify:eval` 10 项全部通过，运行时自检 19 项通过，14 个页面均返回 200。

## 14.2 AI 技术说明

大赛要求重点说明选型理由、集成方式与优化策略，集中写在下面。

**选型理由**（见 4.1）。业务数值全部由本地确定性算法产生，大模型只承担语言组织，因此选型标准主要落在接口兼容性与中文表达质量上，成本次之。项目通过一组环境变量在六家 OpenAI 兼容服务商之间切换，统一使用 `/chat/completions` 协议，不与某一家绑定。

**集成方式**（见 4.2）。AI 接入只有 `/api/chat` 一个入口。请求进入后先做 RAG 检索并把证据注入上下文，再以系统提示中的七条约束要求模型引用证据、不编造数字；模型通过 `tools` 参数并行调用工具，结果以 `role: tool` 回填，最多四轮；输出走 SSE 增量下发，最后交给 `verifyGrounding` 做数值校验。上游超时、限流或缺少密钥时自动切到本地引擎，交互不中断。

**优化策略**（见 4.8）。主要做法有四点：把数值计算与语言生成分开；用端侧 TF-IDF 稀疏检索替代向量库，省去额外依赖并保证离线可用；用意图路由挑选工具，避免把全部工具暴露给模型；对 429 做退避重试，重试耗尽后降级。

## 14.3 创新点

技术创新有五项。

一是双侧三层知识图谱本体。高校供给侧与产业需求侧共用一套本体，宏观、中观、微观三层贯通，诊断、沙盘与路径规划都基于它，不需要各自维护一套数据。

二是三维递进式确定性分析引擎。同质化用课程 Jaccard、知识点重叠率与图拓扑余弦加权；培养目标偏差用 12 项毕业要求的四态矩阵；知识点缺口做跨域语义对齐。三段结果都可以复算。

三是数值可溯源与独立复算。任一分数都能展开计算链，并由独立的装配路径重算比对。

四是领域闸门与运行时自检。跨域错配按领域词袋降权；系统自检覆盖 19 项断言；Agent 评测含自检漏报指标，使 AI 的可信度成为可以测量的数字。

五是端云职责分离。向量化、检索、图算法与 What-if 重算都在端侧完成，云端只做语言组织，因此没有密钥也能运行，断网也能演示。

应用创新有四项。

改革沙盘把诊断结论接到决策上。调整学时或增删产业模块后，五个维度实时重算，并可在学时预算内自动寻优。

岗位能力路径把结论落到学生个体。在知识点共现图与跨课程语义邻接图上求多源最短路径，输出分学期的补强计划与学时预算。

课程矩阵导出把结论落到教学文件上。18 列 CSV 覆盖课程、知识点、学时与缺口判定，教务可以直接导入。

专业目录口径分层解决数据表述问题。试点校抽样专业与全国学科目录观察池分列，每条带来源与标签，避免把观察池误读为试点校开设。
