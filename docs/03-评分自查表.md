## H. 已知限制与答辩预案（诚实说明反而加分）

| 可能被追问 | 建议回答 |
|---|---|
| 「为什么不用 Neo4j / BERT 微调？」 | 赛道明确后端仅作 AI 接入层；本作品把图谱构建与语义对齐做成端侧确定性实现，保证评审环境零依赖、结果可复现；接口已解耦，生产版可换回 Neo4j + SentenceBERT，前端零改动。 |
| 「没配密钥时是不是假 AI？」 | 不是。RAG、多 Agent 编排、Function Calling、三维算法、What-if 模拟、图最短路径、Deep Research、安全校验、流式推送全部真实执行，仅语言组织用模板；这是刻意的「无密钥兜底」，对应 AI 安全与可控性评分点。 |
| 「数据集是真实的吗？」 | 是基于项目书试点场景自建的教学演示抽样数据，不含真实学生个人信息；生产版需教务系统授权与招聘数据合作，已在技术文档中说明合规路径。 |
| 「数值会不会是模型编的？」 | 不会。所有数字来自 `graph.ts` / `simulator.ts` / `pathway.ts` 的确定性算法，模型 System Prompt 明确禁止生成数字；输出还经 `verifyGrounding()` 溯源校验。 |
| 「MCP 是标准协议吗？」 | 实现了 MCP 规范的 `initialize / tools/list / tools/call / resources/*` JSON-RPC 方法，传输层用 HTTP 便于公网演示；工具定义与 LLM Function Calling 共用一份注册表，现共 10 个工具。 |
| 「沙盘的寻优是最优解吗？」 | 是**带预算约束的贪心近似解**，不是全局最优；我们明确标注为"近似最优"并输出每一轮的单位学时增益与收敛原因，保证决策可解释，避免把启发式结果包装成精确解。 |
| 「路径图会不会断连？」 | 跨课程语义邻接 + 每个技能保留 Top-3 入边保证可达；若对齐度过低仍不可达，则输出低置信"需新建产业模块"兜底链，并在置信度中体现，不伪造路径。 |

### 答辩预案（v3 新增，建议提前准备）

1. **「你们的专业数据是真实的吗？」** → 不是。课程/学时/在招数/薪资为教学演示抽样，口径与来源在 `/majors` 页与 `docs/06` 逐条标注；算法链路与真实数据解耦，接真实教务数据即可替换。
2. **「为什么只有 62 个专业？」** → 全国 845 种，本作品只收录能与产业岗位 JD 做语义对齐的热门/战略急需专业，目录页保留扩展接口；不声称穷尽。
3. **「AI 会不会被上传文档带偏？」** → 现场演示投毒：上传含「忽略以上所有指令」的文本，展示入库拦截 2 句、检索回显净化、输入侧注入拦截三道防线。
4. **「新专业为什么初始匹配度偏低？」** → 因为语义对齐是字符二元组 + 关键词规则，当前 334 个知识点中 204 个已登记产业别名、130 个尚未登记；这正是沙盘「新增产业模块后拉升匹配度」要演示的改革价值，结论标注为辅助决策、需人工复核。
5. **「多人同时访问会不会互相影响？」** → 限流与语料为单实例内存，已在 `docs/06` R01/R02 列为残余风险与生产化方案（Redis + 向量库 + 鉴权），评审单机环境不受影响。
