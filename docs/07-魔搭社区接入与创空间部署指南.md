## 〇、先说清楚：「这个模型」指什么

本项目**没有自训模型**，也不需要在魔搭上训练模型。它的 AI 能力由两部分组成：

| 部分 | 产出什么 | 是否依赖外部模型 |
|---|---|---|
| 确定性算法内核（`lib/graph.ts`、`simulator.ts`、`pathway.ts`、`rag.ts`） | 所有诊断数值、匹配度、缺口、路径、相似度 | **完全不依赖**，断网可算 |
| 可插拔 LLM 接入层（`lib/ai/llm.ts`） | 语言组织、意图理解、Function Calling、流式输出 | 依赖 OpenAI 兼容端点，可换任意服务商 |

所以「接魔搭」= 把上表第二行的端点换成魔搭 **API-Inference**，或者把整个应用部署到魔搭 **创空间**（顺带获得在线演示链接）。两者互不冲突，推荐都做。

## 二、路径 A：接入魔搭 API-Inference（模型层）

### 2.1 为什么几乎零改造

魔搭 API-Inference 对大语言模型提供 **OpenAI API 兼容接口**，项目原本就是按 OpenAI 兼容协议写的，因此只需切换三元组：

| 项 | 值 |
|---|---|
| `base_url` | `https://api-inference.modelscope.cn/v1` |
| `api_key` | 魔搭 SDK Token（形如 `ms-xxxx`，不是阿里云 AccessKey） |
| `model` | ModelScope Model-Id，如 `Qwen/Qwen3-Coder-30B-A3B-Instruct` |

官方资料：<https://www.modelscope.cn/docs/model-service/API-Inference/intro>；每个模型页右侧都有可直接复制的 API-Inference 范例代码，**以模型页为准**（模型会上下线）。

> **v5 更新（免重启）**：现在可以直接在网页 **`/models`** 页面选择服务商、粘贴 Token、测试连接并一键启用，无需改 `.env.local`、无需重启服务；密钥仅存服务端进程内存、重启自动回落。完整说明见 `docs/09-网页端大模型接入配置.md`。下面 2.2 的 `.env` 方式仍推荐用于生产 / 创空间部署（配合平台 Secrets）。

### 2.2 前置条件（缺一不可）

1. 注册 / 登录 <https://modelscope.cn>
2. **绑定阿里云账号并完成实名认证** —— 官方明确说明未完成实名无法使用 API-Inference
3. 在 <https://modelscope.cn/my/myaccesstoken> 获取 SDK Token

### 2.3 操作步骤

```bash
# ① 复制模板（模板已默认推荐魔搭）
cp .env.example .env.local          # Windows: copy .env.example .env.local
```

编辑 `.env.local`，只改这两行即可：

```dotenv
AI_PROVIDER=modelscope
MODELSCOPE_SDK_TOKEN=ms-你的真实Token
```

> `AI_BASE_URL` / `AI_MODEL` 保持注释状态，项目会自动使用魔搭预设。
> 若你之前用过 DeepSeek 模板、`.env.local` 里残留 `AI_BASE_URL=https://api.deepseek.com/v1` 与 `AI_MODEL=deepseek-chat`，
> 代码已做兼容识别：切到 `AI_PROVIDER=modelscope` 时会自动忽略这两项模板残留，不会反向覆盖预设。

```bash
# ② 连通性自检（零依赖，不打印 Token）
npm run check:modelscope
npm run check:modelscope -- --tools        # 额外验证 Function Calling
npm run check:modelscope -- --model=Qwen/Qwen3-235B-A22B-Instruct-2507

# ③ 重启服务
npm run dev        # 或 npm run build && npm start
```

验证：访问 `/api/status`，应返回

```json
{
  "mode": "llm",
  "provider": { "id": "modelscope", "name": "魔搭 ModelScope · API-Inference", "throttleProne": true },
  "model": "Qwen/Qwen3-Coder-30B-A3B-Instruct",
  "modelscope": { "tokenConfigured": true, "candidates": [ ... ] }
}
```

然后在 `/copilot` 提问，可看到真实的逐 token 流式输出与 Function Calling 工具轨迹。

### 2.4 模型怎么选

| Model-Id | 适用 | 备注 |
|---|---|---|
| `Qwen/Qwen3-Coder-30B-A3B-Instruct` | **默认**，工具调用稳定、限流相对宽松 | 项目预设值 |
| `Qwen/Qwen3-235B-A22B-Instruct-2507` | 综合推理更强，报告文案更好 | 额度消耗更高 |
| `deepseek-ai/DeepSeek-V3.2` | 中文长文本、诊断报告 | 社区实测支持工具调用 |
| `Qwen/Qwen2.5-VL-72B-Instruct` | 多模态视觉（图片 JD 抽取） | 配 `VISION_MODEL` 使用，复用同一 Token |

社区实测这些模型支持 **Function Calling**，这对本项目的 10 个工具至关重要。若换了不支持工具调用的模型，Copilot 会退化为「只生成文字、不调工具」——功能仍可用，但演示效果下降。

### 2.5 额度、限流与容错（重要）

- 魔搭免费推理采用**动态限流 + 魔粒额度体系**：每日登录发放魔粒，轻量/主流/旗舰模型分别约 0.5 / 1 / 2 魔粒每次；早期宣传口径为「每日 2000 次请求」，**实际额度与单模型限流以控制台为准**。免费服务明确不提供高并发 SLA，勿用于生产。
- 项目已内置针对 `throttleProne` 服务商的 **429 自动退避重试 3 次**（尊重 `Retry-After`，上限 8 秒）；仍失败则 SSE 返回泛化错误并自动切回本地确定性引擎，演示不会中断。
- **推理模型兼容**：R1 / QwQ 等模型把思维链放在 `delta.reasoning_content` 而不是 `delta.content`。`readSSE()` 已同时解析两者，并把推理长度作为「推理智能体 · 思维链」步骤事件可视化（对应赛道「思考状态可视化」），不会得到空答案。
- **断网 / 无 Token / `DEMO_MODE=true`**：全部页面、诊断、沙盘、路径、Deep Research 仍由本地引擎完整演示，零 token 消耗。这是评审现场的保底方案。

### 2.6 本轮代码改动清单

| 文件 | 改动 |
|---|---|
| `src/lib/ai/providers.ts`（新增） | 5 家服务商预设、魔搭模型候选、Token 脱敏工具 |
| `src/lib/ai/llm.ts` | `AI_PROVIDER` 解析、`MODELSCOPE_SDK_TOKEN` 别名、模板残留兼容、429 退避、`reasoning_content` 兼容与思维链事件 |
| `src/app/api/status/route.ts` | 暴露 provider / 魔搭元信息 / 候选模型（**不返回密钥**） |
| `.env.example` | 改为魔搭推荐配置，含注册、实名、模型与额度说明 |
| `scripts/check-modelscope.mjs`（新增） | 一键连通性 + Function Calling 自检 |
| `package.json` | 新增 `check:modelscope`、`audit:data` 脚本 |

## 三、路径 B：部署到魔搭创空间（在线演示链接）

> 本章是概览。**需要照着一步步点控制台时，请直接看 `docs/08-创空间部署逐步操作手册.md`**：
> 那里包含干净上传包的生成、网页/Git 两种上传方式、Secrets 配置、构建与运行日志、
> 部署后一键验收、URL 挂载路径诊断、已知限制与完整排错表。

### 3.1 为什么必须用 Docker 类型

创空间支持 4 种 SDK：`Static HTML` / `Gradio` / `Streamlit` / `Docker`。本项目是 Next.js 全栈应用，**页面之外还有 11 个 API Routes**（SSE 对话、RAG、MCP、文档解析），纯静态部署会让所有 AI 功能失效，因此选 **Docker**。

创空间 Docker 的硬性要求：

- 服务必须监听 **7860** 端口
- 前后端合并到**同一个容器**
- 项目根目录提供 `Dockerfile` 与 `ms_deploy.json`

这三点本仓库已全部满足：`Dockerfile` 用 Next.js `output: 'standalone'` 产出单容器服务，`PORT=7860`、`HOSTNAME=0.0.0.0`，`ms_deploy.json` 指定 `sdk_type: docker` 与免费 2vCPU/16G 资源档。

### 3.2 本地先验证镜像（可选但强烈建议）

```bash
docker build -t puhe-ai-web .
docker run -p 7860:7860 \
  -e MODELSCOPE_SDK_TOKEN=ms-你的Token \
  -e AI_PROVIDER=modelscope \
  puhe-ai-web
# 浏览器打开 http://localhost:7860 ，并访问 /api/status 确认 mode=llm
```

### 3.3 创空间控制台操作

1. 用以下任一入口进入创建页：直接打开 <https://modelscope.cn/studios/create>；或右上角头像下拉 →「**创建创空间**」；或创空间首页顶部「**我要创建**」。需先登录（未登录不显示创建按钮）
2. 官方把创建**方式**分为「编程式创建 / 交互式创建」，编程式创建下再用**创建页顶部标题栏**切换「自定义创建」与「**快速创建并部署**」两种**模式**（后者为 Beta 灰度，可能不显示）。填名称（如 `puhe-edu-graph`）、描述、可见性（参赛建议**公开**）
3. 若 Beta 模式可见：上传 `studio-package/` 内的全部文件并触发部署；**若找不到该模式**，走稳定路线：保持「自定义创建」→ 创建空仓库 → 部署设置里选 Docker SDK → `git push origin master` 上传包内文件（详见 `docs/08` 第 4.4 节）。文件须含 `Dockerfile`、`ms_deploy.json`、`src/`、`package.json`、`package-lock.json`；`node_modules`、`.next`、`.env*` 由 `.dockerignore` 排除
4. 在创空间「设置 → 变量与密钥」中把 `MODELSCOPE_SDK_TOKEN` 添加为 **Secret（密钥变量）**，另外可加明文变量 `AI_PROVIDER=modelscope`
   - ⚠️ **绝对不要**把 Token 写进 `ms_deploy.json`、Dockerfile 或任何提交到仓库的文件
5. 网页路线点「确认创建并部署」、Git 路线推送后自动触发；等待构建完成（首次约 3–5 分钟），在「构建日志 / 运行日志」排错
6. 完成后得到公开链接：`https://modelscope.cn/studios/<你的账号>/<空间名>`

> 魔搭官方还提供 `ms-studio-deploy` / `modelscope-studio-deploy` Skill 与 `ms` CLI，可用 `ms deploy` 更新已部署空间、看日志、管理 secrets；熟悉命令行的话比网页上传更适合迭代。

### 3.4 部署到创空间后的参赛收益

- **在线演示加分项**：把链接写进 README、PDF 技术文档与报名材料
- **密钥合规**：Token 存在平台 secrets，公开仓库里只有 `.env.example` 模板，满足赛道「密钥不得入库」
- **与 A 天然叠加**：创空间容器里的 `/api/chat` 会直接调用魔搭 API-Inference，形成「魔搭托管应用 + 魔搭托管模型」的完整闭环，答辩时是很好的叙事

### 3.5 Docker 部署的已知注意点

| 问题 | 处理 |
|---|---|
| `unpdf` / `mammoth` 在 API Route 里动态 `import`，standalone 文件追踪可能漏掉 | Dockerfile 额外把完整 `node_modules` 复制进 runner，保证 PDF/DOCX 上传可解析 |
| 静态资源 404 | 已显式 `COPY .next/static ./.next/static` |
| 只监听 localhost 导致外部访问不到 | 已设 `HOSTNAME=0.0.0.0` |
| 免费资源档内存 | `platform/2v-cpu-16g-mem` 足够；不要选需要申请的 xGPU 档 |
| 端口不是 7860 | 创空间会判定启动失败，不要改 `PORT` |

## 六、故障排查速查表

| 现象 | 原因 | 处理 |
|---|---|---|
| `401 / 403` | Token 错误、未绑定阿里云、未实名 | 重新获取 Token；完成绑定与实名认证 |
| `429` | 动态限流 / 当日额度用尽 | 项目自动退避 3 次；仍失败会降级本地引擎；稍后重试或换轻量模型 |
| `404 model not found` | Model-Id 已下线 | 到目标模型页复制最新 API-Inference 范例 ID，`AI_MODEL=` 覆盖 |
| 回复为空 / 只有 `FALLBACK_ANSWER` | 推理模型只返回 `reasoning_content` | 已兼容；若仍出现，换非推理模型或检查 `check:modelscope` 输出 |
| Copilot 不调用工具 | 模型不支持 Function Calling | 换 `Qwen/Qwen3-Coder-30B-A3B-Instruct` 等实测支持工具调用的模型 |
| 图片上传无抽取结果 | 未配 `VISION_MODEL` | 配 `VISION_MODEL=Qwen/Qwen2.5-VL-72B-Instruct`，复用同一 Token |
| 创空间部署后页面 502 | 端口 / 绑定地址 / 构建失败 | 确认 `PORT=7860`、`HOSTNAME=0.0.0.0`，查看创空间运行日志 |
| `/api/status` 一直 `mode=local` | `DEMO_MODE=true` 或 Token 未注入 | 关掉 DEMO_MODE；检查 secrets 变量名是否为 `MODELSCOPE_SDK_TOKEN` |

### 本地构建的环境兼容说明（与魔搭无关，仅本机排查用）

在部分 Windows 沙箱 / 杀软环境中，Next.js 14 的多个 build worker 会并发以追加方式打开
`<distDir>/trace`，偶发 `EPERM: operation not permitted, open '...\.next\trace'`，导致编译前崩溃。
追踪数据只用于性能分析、不影响产物；仓库提供 `scripts/no-trace.cjs` 把它转为内存空流：

```bash
# 仅在遇到 EPERM 时使用；Docker 构建与正常环境直接 npm run build
NODE_OPTIONS="--require=./scripts/no-trace.cjs" npm run build
```

另外，**本地构建前请先停掉正在运行的 `next start`**：运行中的服务也会写 `.next/trace`，
与构建进程争用同一文件句柄。这是本轮实际踩到并定位到的两个原因。

> 说明：本轮无法代替你完成魔搭账号注册、实名认证、Token 获取与创空间点击部署，这些步骤必须本人操作；仓库侧的所有代码与配置已准备就绪。
