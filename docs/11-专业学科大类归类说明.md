# 专业学科大类自动归类说明（v7 建立 / v8 扩样）

> 适用版本：v8（2026-11-10）｜项目根目录：`E:\WorkBuddy\项目\谱合产教`
> 实现：`src/lib/major-taxonomy.ts`（纯函数）｜接口：`GET /api/majors`｜页面：`/majors`

## 1. 为什么要做两套分类

系统原有 `MAJOR_GROUPS` 是**按数据来源/主题**分的 10 类（信息技术与数字经济、芯片与电子信息、数字法治与合规等），回答的是「这些专业从哪些权威榜单来的」。另一套是**按学科门类**的分类，回答的是「这些专业属于什么学科、和哪些产业岗位对齐」。两套分类并存、互不覆盖：

| | 来源分类（v3 / v8 扩为 10 类） | 学科大类（v7 建立 / v8 扩样） |
| --- | --- | --- |
| 依据 | 教育部新增专业 / 绿牌 / 热度榜 / 布点增长 / 专业目录补录 | 专业名称 + 学院 + 现有学科类 + 课程体系 |
| 用途 | 数据来源可追溯、热度标签 | 学科结构分析、按类筛选、自动总结 |
| 入口 | `/api/majors?group=`、目录页「分类分布」 | `/api/majors?discipline=`、目录页「学科大类自动归类」 |

### 归类口径的几处判断

- 「电气工程及其自动化」归**电力工程**而非电气自动化：课程体系以电力系统分析、继电保护、电机学为主。
- 「智慧水利」「农业水利工程」归**电力工程**：项目书试点场景为水电/灌区，与发电输配同属电力工程链。
- 「新能源科学与工程」「储能科学与工程」「碳中和科学与工程」单独成**新能源与双碳**，避免把电力工程类撑得过大。
- 「时空信息工程」「智慧城市与空间规划」归**交通工程**：北斗导航、低空与城市空间规划是交通基础设施的数字化侧。
- 「智能视听工程」归**芯片与电子信息**：属电子信息类、课程为信号与系统/数字信号处理。
- 「健康与医疗保障」归**医学**：医学院开设、依托临床医学基础与健康大数据。
- v8 新增的 8 个法学专业全部由 `MAJOR_DISCIPLINE` **精确锁定到法学**：它们名称含「国际/经济/信用」、课程含「微观经济学/国际商法」，若只走关键词会被经济贸易类抢先命中。
- 「合规」不作为法学关键词：它是「安全合规与等保」等多门课程名的组成部分，单独使用会让非法律专业误命中；改用「纪检监察 / 涉外法治 / 法学院」等专指词。
- 每个专业**只归一类**，不重复计数；口径有异议时改 `MAJOR_DISCIPLINE` 一处即可，页面与统计自动更新。

## 3. 自动归类规则（三级优先）

1. **精确映射**：`MAJOR_DISCIPLINE` 为当前 62 个专业逐一指定类别，消除关键词歧义，结果可复现。
2. **语义关键词**：新增专业未登记时，把 `专业名 + 学院 + 现有学科类 + 课程名` 拼成文本，按「指定类优先 → 自动类」顺序匹配；同类内长关键词优先（如「计算机科学与技术」先于「计算机」）。命中依据以 `evidence` 字段回传，页面可审计。
3. **兜底**：未命中任何关键词时进入「其他交叉专业」，并在覆盖率与总结里显式显示待补充数量。

规则不调用大模型、不依赖数据库与网络，离线可跑；新增专业只要名称含关键词就会自动进入对应大类并出现在总结中。

## 4. 自动总结

`buildTaxonomy()` 会根据实时数据生成 4 条总结（页面「自动归类总结」区块直接展示），当前输出为：

- 共收录 62 个专业，完成学科归类 62 个，覆盖率 100%，无未归类专业。
- 7 个指定学科类收录 42 个专业（67.7%），数量最多的是法学 9 个、计算机 8 个、电力工程 6 个。
- 其余 20 个专业按名称、所属学院与课程体系语义自动归为 6 类：芯片与电子信息（6）、新能源与双碳（4）、土木水利与建造（3）、教育文法与传媒（3）、材料与化工（2）、时空海洋与公共安全（2）。
- 归类依据可在每个专业上查看（精确映射 / 关键词命中 / 兜底），新增专业无需改动页面即可自动进入统计。

每个类别还单独生成小结：`N 个专业 · 占比 X% · 覆盖 M 个学院 · 平均热度 H`。

## 5. 接口与页面

| 入口 | 说明 |
| --- | --- |
| `GET /api/majors` | 返回 `taxonomy`（`total / coverage / specifiedCount / autoCount / categories[] / highlights[] / method`）与 `disciplineOptions`；每行 `rows[]` 带 `discipline / disciplineName / disciplineKind / disciplineBy / disciplineEvidence`，以及口径字段 `scope`（`试点校` / `观察池`） |
| `GET /api/majors?discipline=law` | 只返回法学类 9 个专业；`taxonomy` 仍基于全量 62 个，不受筛选影响 |
| `GET /api/majors?discipline=computer` | 只返回计算机类 8 个专业，统计口径同上 |
| `/majors` | 「学科大类自动归类」卡片：覆盖率统计、自动总结、13 张类别卡（指定/自动徽标、专业名单、类别小结），点击类别即筛选下方专业清单；顶部下拉也可切换 |
| 专业卡片 | 显示学科大类徽标、标签徽标与 **口径徽标**；观察池专业在代码行标注「学科目录观察池（非试点校开设）」，展开详情可查看归类依据 |

## 7. 扩展方式

- 新增专业：在 `dataset.ts` / `hot-majors.ts` 加入后，若名称命中关键词会自动归类；需要精确口径时在 `MAJOR_DISCIPLINE` 补一条（含「经济/国际/数据」字样的专业尤其建议锁死）。
- 配套数据：新课程名必须写进 `extraCourseSeeds`，新技能必须被某个 `extraJobs` 引用，否则 `dataIntegrityReport()` 会报错或审计脚本会提示孤立实体。
- 新增/调整大类：改 `DISCIPLINE_CATEGORIES` 的 `name / description / keywords`，页面、统计、总结全部自动跟着变，无需改前端。
- 验证：启动服务后运行 `npm run verify:majors`（22 项断言）与 `npm run audit:data`（引用闭合），无需大模型与 GPU。
- 若继续扩样，建议优先补**现有专业的课程深度**（当前约 8 门/专业）而非继续增加专业数量；真实本科培养方案为 40–60 门，广度继续扩张会稀释数据可信度。
