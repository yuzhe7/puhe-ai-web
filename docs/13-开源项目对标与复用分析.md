### 0.3 三个关键判断

1. **定位相似但无成熟对标 = 原创性成立**。MOOCCubeX/MOOCCube 只有「课程—视频—概念—学生」供给侧；ESCO、O*NET、LAiSER、future-of-work-data 只有「职业—技能」需求侧。**把两侧放进同一张三层图谱并做跨域对齐，GitHub 上找不到可直接对标的成熟开源项目**；同理，「专业同质化三维加权诊断」与「What-if 培养方案反事实沙盘」也只在通用图算法库与静态 OBE 报表系统里有零散影子。开源资源应定位为 **schema / 算法 / 评测参照**，不是系统依赖。
2. **整体替换核心是净损失**。自研的 `llm.ts` 多服务商运行时、10 工具确定性意图路由、端侧 TF-IDF RAG、内存态密钥 + SSRF、失败降级本地引擎、MCP JSON-RPC 端点、Xiaomi-OCR-0 通道，正是竞赛看点。套 AI SDK 重写 `llm.ts`、换 LangGraph 做编排、用官方 SDK 替换 MCP 端点、引 Postgres+向量库，都会把亮点变成调包。正确姿势：**协议对齐 + 前端/测试层复用 + 算法思路移植**。
3. **该补的是五项工程短板，不是新框架**：运行时 schema 校验、浏览器级 E2E、事件/异步错误边界、工业化密钥扫描、确定性算法的评测证据。这五项全部能离线跑、纯 TS/单镜像、不伤原创性。

## 1. A 类：可借鉴（只读设计，不引入代码/依赖）

### 1.1 平台与架构

#### A1. Dify — https://github.com/langgenius/dify
- **概况**：LLM 应用开发平台标杆，Python + Next.js；极活跃；GitHub 许可字段 `NOASSERTION`（自定义开源许可，附加条款未逐条核实）。
- **相似点**：`tools.ts`（工具注册）、`rag.ts`（检索链路）、`research.ts`（多 Agent）、MCP 端点。
- **可借鉴**：① **RAG Pipeline 节点化**——抽取→分块→embedding→检索→重排，每步可单测、可替换，正是 `rag.ts` 单体函数的对照架构；② 工具/MCP 的市场式注册 + 沙箱执行；③ **LLMOps 闭环**：应用日志→标注→数据集回流→评测，补本项目「无评估」短板。
- **预期价值**：把「检索链路可解释、可评测」写进答辩，比堆功能更有说服力。
- **局限**：自定义许可含多租户/品牌条款需核对；Python 全栈 + 多容器（Postgres/Redis/向量库），整体照搬等于交出原创性。
- **优先级**：**P1**（只读借鉴节点拆分与评估闭环）。

#### A2. FastGPT — https://github.com/labring/FastGPT
- **概况**：中文知识库 + 可视化工作流，TypeScript/Next.js；**FastGPT Open Source License 明确不允许提供 SaaS**、商用须保留版权。
- **相似点**：`rag.ts`、`tools.ts`、`/api/chat`、MCP 端点；与「产教融合」场景最接近的中文平台。
- **可借鉴**：① 混合检索 + 重排；② **QA 拆分导入 + chunk 可增删改**（实时入库的可维护版本）；③ 对话中**引用可查看/修改/删除**（检索溯源的 UI 侧）；④ 完整调用链日志 + 节点日志 + 评测；⑤ `labring/aiproxy` 的多上游负载均衡与失败切换（正是「失败降级本地引擎」的加强版）。
- **预期价值**：引用溯源交互与多上游故障切换可直接提升 `/data`、`/copilot` 的可信度。
- **局限**：**许可禁止 SaaS**，与对外演示/托管直接冲突；Mongo/PG/向量库部署重。
- **优先级**：**P1**（工程实践最贴合，但许可必须先确认）。

#### A3. Open WebUI — https://github.com/open-webui/open-webui
- **概况**：Svelte + Python；**Open WebUI License 要求保留 branding**，`NOASSERTION`。
- **相似点**：`runtime-config.ts` 多 provider 运行时切换、RAG 通道。
- **可借鉴**：**Pipelines** 把 RAG/限流/工具做成独立插件服务的「过滤器链」，主应用与扩展解耦；`LICENSE_HISTORY` 的许可沿革管理是工程治理范本。
- **预期价值**：为「插件化工具」提供架构参照。
- **局限**：许可陷阱（改标识/再分发有合规风险）；技术栈不一致；体量无法局部摘取。
- **优先级**：**P2**（架构思路可读，代码与许可都不宜复用）。

#### A4. LobeHub（原 Lobe Chat）— https://github.com/lobehub/lobehub
- **概况**：Next.js/TS；**LobeHub Community License（非 OSI 标准）**；已从聊天框架转型 Agent 团队协作平台。
- **相似点**：`tools.ts` 插件 manifest、`research.ts` 多 Agent 分工。
- **可借鉴**：① 插件 = Function Calling manifest 的注册/发现；② Agent Team 的 **sequential / parallel / iterative / debate 四种编排模式枚举**，可直接映射 Deep Research 分工；③ 40+ provider 的环境变量清单组织法。
- **预期价值**：为 `research.ts` 补齐可枚举的编排模式。
- **局限**：非标准开源许可，商用/竞赛分发需法务确认；项目方向已变，旧插件文档不再对应当前代码。
- **优先级**：**P2**。

#### A5. LangGraph — https://github.com/langchain-ai/langgraph
- **概况**：MIT，Python 为主（另有 JS 版）；官方自述已收敛为底层 runtime，别再当友好 Agent SDK。
- **相似点**：`research.ts` 长任务编排。
- **可借鉴**：**durable execution + checkpoint**（失败从断点恢复）、**interrupt/resume 人工介入**、短期工作记忆与跨会话长期 memory 分离、channel reducer 增量状态编码。
- **预期价值**：Deep Research 长任务与「用户改研究计划再执行」的可靠实现范本。
- **局限**：引入会把自研确定性意图路由换成通用图引擎，原创性冲突明显。
- **优先级**：**P1**（借三个概念，不引运行时）。

#### A6. LlamaIndex — https://github.com/run-llama/llama_index
- **概况**：MIT，Python；官方重心已转向商业文档解析（LlamaParse），OSS 框架「可用但非重点」。
- **相似点**：`rag.ts`、`ocr.ts`。
- **可借鉴**：`Document → Node → TextChunk` 分层抽象、`SentenceSplitter`、retriever/reranker 可替换插槽、`storage_context.persist()` 内存↔磁盘索引；**`_static` 内嵌 nltk/tiktoken 缓存 + `gh attestation verify` 产物校验**，对端侧离线与供应链安全很有启发。
- **预期价值**：给端侧 TF-IDF 补一套术语与持久化契约。
- **局限**：方向已变、Python 栈、向量索引体系与本项目定位不同。
- **优先级**：**P2**。

#### A7. microsoft/graphrag — https://github.com/microsoft/graphrag ／ A8. microsoft/autogen — https://github.com/microsoft/autogen
- **概况**：前者 MIT 但 README 明写 **largely in maintenance mode，不接新 PR/新功能**；后者 README 明写 **2026-10-16 已归档停维**，继任者 Microsoft Agent Framework。
- **相似点**：`graph.ts` 图谱增强检索、`research.ts` 多 Agent。
- **可借鉴**：仅作论文/概念与「社区图谱摘要」思路引用。
- **预期价值**：写进调研附注可体现选型严谨度。
- **局限**：维护模式/已归档，**写进技术选型会直接减分**。
- **优先级**：**P2（明确排除）**。

#### A9. vercel/chatbot — https://github.com/vercel/chatbot （原 `vercel/ai-chatbot`）
- **概况**：Next.js App Router 官方聊天模板；`NOASSERTION`、`is_template: true`。
- **相似点**：`runtime-config.ts`、`/api/chat`。
- **可借鉴**：`lib/ai/models.ts` 的**静态模型清单 + per-model provider 路由**（本项目网页端多服务商配置的极简原型）；`.env.example` 里「不要提交 `.env`」的密钥边界说明；AI Gateway OIDC 与非 Vercel 部署 API Key 的**双路径降级**；`app/(chat)` 路由组织。
- **预期价值**：配置表结构与密钥边界写法可直接抄。
- **局限**：绑定 Vercel 生态（Gateway/Neon/Blob）；许可 `NOASSERTION` 不宜复制代码。
- **优先级**：**P1**。

#### A10. OpenSPG / KAG — https://github.com/OpenSPG/KAG （引擎 https://github.com/OpenSPG/openspg ，Apache-2.0 / Java）
- **概况**：蚂蚁 + OpenKG 的语义增强可编程图谱与知识增强生成框架；Apache-2.0。
- **相似点**：`graph.ts` 双侧三层图谱的 schema 约束。
- **可借鉴**：**领域模型约束的知识建模**——显式声明「专业/课程/知识点/岗位/技能」实体类型、属性与关系约束，防止 TS 内存数组退化成无约束字典；KAG 的 **Knowledge-Chunk 互索引**与「生成内容回链原始引用」。
- **预期价值**：规范 `graph.ts` 类型定义；回链引用可直接补 `rag.ts` 溯源。
- **局限**：Java 引擎 + Python 框架对竞赛级 Next.js 过重；偏 LLM/RAG，与「确定性零幻觉」定位不同。
- **优先级**：**P1**（借 schema 约束思想，不部署引擎）。

### 1.2 领域建模与评测

#### A11. MOOCCubeX — https://github.com/THU-KEG/MOOCCubeX
- **概况**：清华 THU-KEG 大规模 MOOC 自适应学习知识仓库；**GPL-3.0**；Python；`pushed_at 2023-12-27`，近停更。
- **相似点**：`dataset.ts`、`graph.ts`、`pathway.ts`、`major-taxonomy.ts`。
- **可借鉴**：`course–video–concept` 三层实体 + **concept graph（上下位 taxonomy + 先修链）**；以「学生学习某课程某知识点」三元组为数据单元；先修链用 taxonomy 信息 + 视频顺序依赖缩减候选对再标注、远监督扩增。**三层结构与本项目几乎同构，先修链可引入 `pathway.ts` 的 DAG 约束**。
- **预期价值**：`graph.ts` / `dataset.ts` schema 的首要参照；为学习路径提供先修依据。
- **局限**：**GPL-3.0 具传染性**，整体引入与竞赛许可冲突；无岗位/技能产业侧；数据为中文 MOOC 视频粒度，且久未更新。
- **优先级**：**P0（只借 schema 与建模，不采用数据）**。

#### A12. MOOCCube 原版 — 非 GitHub（数据集托管 `moocdata.cn`，论文 ACL 2020）
- **核实结论**：`api.github.com/repos/THU-KEG/MOOCCube` 返回 **404**，不提供仓库 URL。
- **可借鉴**：概念 taxonomy 以 CNCTST 跨语言术语表为底（对应 `major-taxonomy.ts` 归类口径）；先修链定义「若 A 有助理解 B 则 A→B」；PREREQ-S 用观看序列作语义信号。
- **预期价值**：归类与先修关系的学界依据，可作论文引用。
- **局限**：无 GitHub 仓库，不能作依赖；许可不明；无产业侧。
- **优先级**：**P1（方法论引用）**。

#### A13. pyKT — https://github.com/pykt-team/pykt-toolkit （MIT，活跃）
- **相似点**：`pathway.ts` 掌握度 + 全项目「诊断算法评测集构造」。
- **可借鉴**：**标准化预处理 + 5 种预测场景 + fold 切分 + 统一指标**；`noise_add.py` 按噪声率生成鲁棒性评测集。可照此给 62/109/334 数据做「扰动注入 → 诊断结果稳定性」评测。
- **预期价值**：补上确定性算法最缺的**可信度证据**（本项目目前只有引用完整性审计，无算法评测）。
- **局限**：面向学生答题序列，本项目无行为日志；只借评测框架，KT 模型不可套用。
- **优先级**：**P1**。

#### A14. pyBKT — https://github.com/CAHLR/pyBKT （MIT，活跃）
- **可借鉴**：四参数 `{p(L0), p(T), p(S), p(G)}` 的可解释掌握度递推，为「知识点缺口」提供概率化学界口径，作确定性诊断的对照论证。
- **预期价值**：答辩中回答「为什么用确定性而非模型」的量化依据。
- **局限**：需逐学生答题序列；引入会改变作品定位。

## 4. 原创性与合规边界（明确不做什么）

1. **不整体替换自研核心**：`llm.ts` 多服务商运行时、10 工具确定性意图路由、端侧 TF-IDF、内存态密钥 + SSRF、失败降级本地引擎、MCP JSON-RPC 端点、Xiaomi-OCR-0 通道——替换为 AI SDK / LangGraph / 官方 MCP SDK / 向量库，都是净损失。
2. **不引入常驻服务**：pgvector+Postgres、Qdrant、Milvus、Chroma Server、Neo4j/Apache AGE、Langfuse 全栈、K8s/Helm、多服务 Compose。违背「无数据库、standalone 单镜像、7860 单端口」。
3. **不引入 Python 重栈**：MinerU、docling、PaddleOCR、DeepKE（仅离线脚本例外）、LLM Guard（且已归档）、NeMo Guardrails/Rebuff、Ragas/DeepEval。与 TS 单镜像冲突。
4. **不引入近似检索与 LLM-as-judge**：会破坏「确定性、可复现」这一核心卖点。评估一律用固定题库 + 确定性断言。
5. **许可红线**：MOOCCubeX **GPL-3.0** 只借 schema；`ScoreOBE`、`future-of-work-data`、`NetworkX`、`MinerU`、`pgvector`、`Langfuse`、`LobeHub`、`Open WebUI`、`FastGPT`、`Vercel AI SDK`、`vercel/chatbot`、AG Grid 均为 `NOASSERTION`／自定义／无声明，**代码或产物并入 `pack-studio.mjs` 上传包前必须逐项核对 LICENSE**；FastGPT 明确禁止 SaaS、Open WebUI 强制保留 branding。
6. **不把停维项目写进技术选型**：`microsoft/autogen`（已归档）、`microsoft/graphrag`（维护模式）、`protectai/llm-guard`（已归档）、`visjs/vis`（已归档无许可）、`Tremor`/`RecBole`/`ScoreOBE`（长期停更）。把它们列在调研附注里反而加分。
