# 专业深链接自动匹配说明（v9）

> 适用版本：v9（2026-11-10）｜项目根目录：`E:\WorkBuddy\项目\谱合产教`
> 实现：`src/lib/major-context.ts`｜入口：`/majors` 卡片底部「沙盘 / 诊断 / 路径」

## 1. 解决的问题

`/majors` 每张专业卡片底部有三个跳转按钮。改造前链接只带 `major` 参数，三个目标页面虽然会读取专业，但**目标岗位和对比专业仍停留在硬编码默认值**，导致跳转后出现无意义的组合：

| 页面 | 改造前（示意图） | 问题 |
| --- | --- | --- |
| `/diagnosis` 专业两两对比 | 低空技术与工程 ↔ 软件工程 | 对比专业是默认值，与来源专业无关 |
| `/path` 能力路径 | 目标岗位 AI应用开发工程师 / 所在专业 新能源科学与工程 | 岗位与专业不匹配 |
| `/simulate` 改革沙盘 | 目标专业 计算机科学与技术 / 目标岗位 AI应用开发工程师 | 未带上来源专业对应的岗位 |

改造后，三个链接自动携带「这个专业最相关的岗位」和「这个专业最该拿来对比的专业」，目标页面读入即开始分析或对比，用户不需要再手动选一遍。

## 2. 参数协议

`buildMajorLinks()` 由卡片行数据生成三个 URL，所有参数都做 `encodeURIComponent`：

| 按钮 | 链接 | 参数含义 |
| --- | --- | --- |
| 沙盘 | `/simulate?major=X&job=Y` | X = 目标专业，Y = 该专业契合度最高的岗位 |
| 诊断 | `/diagnosis?tab=macro&major=X&compare=Z` | X = 专业 A，Z = 该专业同质化最高的对比专业 B |
| 路径 | `/path?major=X&job=Y` | X = 所在专业，Y = 该专业契合度最高的目标岗位 |

按钮的 `title` 会提示将自动匹配到哪个岗位 / 专业，鼠标悬停即可确认。

## 3. 匹配依据（确定性，不经大模型）

匹配值直接复用 `/api/majors` 已经算好的两列结果，不新增推理、不引入随机性：

- **目标岗位 Y** = `matchedJobs[0].title`，由 `crossSideMatch(专业, 岗位)` 在全部岗位上算分、过滤 `score >= 0.3` 后取最高分
- **对比专业 Z** = `topRisk.other`，由 `similarityMatrix()` 取与该专业同质化评分最高的另一个专业（课程 Jaccard × 0.3 + 知识点重叠 × 0.4 + 图拓扑余弦 × 0.3）

示例（与目录页卡片显示一致，可用 `/api/majors?q=低空技术与工程` 复核）：

```
专业：低空技术与工程
匹配岗位：智能建造工程师 0.59 > 时空数据工程师 0.45 > GIS/BIM工程师 0.44
同质化最高：时空信息工程 S=0.288
→ 沙盘  /simulate?major=低空技术与工程&job=智能建造工程师
→ 诊断  /diagnosis?tab=macro&major=低空技术与工程&compare=时空信息工程
→ 路径  /path?major=低空技术与工程&job=智能建造工程师
```

## 4. 三条自动匹配链路

1. **目录页跳转（主链路）**：卡片行数据里已有 `matchedJobs` 与 `topRisk`，生成链接时直接带上 Y / Z，跳转后立刻生效，**零额外请求**。
2. **只带专业的深链接（兜底）**：命令面板、手动 URL 或未来其他页面若只传 `?major=X`，目标页调用 `autoMatchJob()` / `autoMatchCompare()` 请求 `/api/majors?q=X` 按名称精确取回该行，自动补齐 Y / Z。
3. **页内切换专业（联动）**：用户在目标页手动切换「目标专业 / 所在专业 / 专业 A」时，自动重新匹配对应的岗位或对比专业；`/path` 同时清空「已掌握知识点」。**手动改岗位或对比专业则尊重用户选择**，不覆盖。

模块内用 `jobMatchSeq` / `compareMatchSeq` 做匹配序号，用户快速连续切换专业时丢弃过期响应，避免旧结果覆盖新选择。若某专业没有匹配岗位（全站仅个别专业 `matchedJobs` 为空）或没有同质化对象，链接省略对应参数，由目标页保留原有默认值，不会出现空选项。

## 5. 为什么「匹配完成 = 自动开始分析」

三个页面在 state 变化后本来就有自动重算机制，因此不需要额外的「开始分析」按钮：

| 页面 | 自动触发机制 |
| --- | --- |
| `/simulate` | `major / job` 变化 → `GET /api/simulate` 拉取基线方案 → `plan` 变化后 260ms 防抖 `POST /api/simulate` 实时重算五维指标 |
| `/diagnosis` | `pair = simRows.find(...)` 由 `useMemo([simRows, majorA, majorB])` 计算，专业 A/B 一变立即刷新同质化评分与三项分解 |
| `/path` | `useEffect([job, major, known, plan])` 直接 `POST /api/path` 重新规划最短学习路径与学时预算 |

页面在自动匹配成功时显示一行提示（含匹配依据与分数），例如「已按「低空技术与工程」自动匹配目标岗位「智能建造工程师」· 契合度 0.59 · 已自动重新规划学习路径」，让评审能直观看到上下文确实被带过来了。

## 7. 验证

启动服务后执行：

```bash
npm run verify:links     # 深链接自动匹配：跨 5 个学科大类逐项校验
npm run verify:majors    # 专业目录与归类回归
npm run audit:data       # 数据引用闭合
```

`verify:links` 对每个样本专业会校验：目录行存在、`matchedJobs[0]` 与 `topRisk.other` 可解析、三个带参链接返回 200、`/api/simulate` 接受自动匹配岗位、`/api/path` 岗位列表包含该岗位、相似度矩阵中确实存在这组对比 pair；另做源码静态断言（四个页面均引用匹配模块、含竞态保护）、`/api/status` 能力注册与 12 个页面 200。
