## 1. 逐步操作脚本（整段复制给 Muse）

```

- 视口固定 1919×992，浏览器缩放 100%，使用你受管浏览器里已有的会话
- 全程不要开启新的无头浏览器
- 每一步操作前截一张图、操作并等待界面稳定后再截一张图
- 截图保存为 shots/s01-intro.png 这类命名（编号与下面步骤一一对应）
- 不要滚动超过一屏；不要输入任何真实账号密码
```

## 2. 旁白（按 state 对齐，供 Muse TTS 生成）

> 每段控制在 20–30 秒。若 Muse 的 TTS 不支持中文，改用剪映「文本朗读」，把这段直接粘进去。

**S01–S02　开场 + 总览**

> 高校每年都在调整专业和课程，但依据往往来自经验判断。这个专业是不是开得太多？课程是不是已经落后产业三年？学生毕业到底能不能对上岗位？我们做了一个能回答这三个问题的平台——谱合产教。
>
> 首页是平台的驾驶舱。这里是我们覆盖的规模：62 个专业、109 门课程、334 个知识点、38 个岗位，背后是 28640 条岗位需求样本。右边这条实时洞察流，每一条都来自真实的诊断计算，不是写死的文案。

**S03–S06　三维诊断**

> 诊断分三层递进。宏观看专业布局——这是 62 个专业两两之间的同质化热力图，颜色越深，两个专业越像。右边是高风险专业对：软件工程和计算机科学与技术，综合相似度 0.79。中观看培养目标——12 项工程教育认证毕业要求，把校内覆盖度和产业需求度放在一起比，红色就是培养不足的项。微观落到知识点——以《数据结构》为例，六个知识点逐个判定：应加强、保持、还是可精简。

**S07–S09　数值溯源**

> 但最常被问的一个问题是：这些数字凭什么可信？所以我们给每一个分数都做了溯源。点这个岗位匹配度，右边滑出完整计算链：先取该专业覆盖的知识点，再对岗位的每项技能求最大语义对齐，按需求强度加权求和、归一化，最后乘以领域亲和度——这一层专门避免把非医学专业匹配到临床岗位。最后是复算校验：页面值和我独立重跑的结果一致，绿色代表通过；任何一个数对不上，这里就会标红。

**S10　系统自检**

> 光有溯源还不够——数据本身有没有断链？算法会不会悄悄漂移？这是系统自检页，19 项断言分三类：数据类查五张表的引用正反向闭合与规模一致；算法类查相似度矩阵两次计算是否逐项一致、有没有非有限值，还有两个回归断言——泛化别名不再虚高、领域闸门确实生效；运行时类查限流、RAG 召回和导出结构。全部通过返回 200，有失败项就返回 503。

**S11　Agent 评测**

> 工程上有自检，那 AI 本身的质量怎么证明？这里 28 条固定用例，分检索、诊断、数值、安全、边界五类，离线可跑、零 token。四个指标：实体召回，回答有没有说到点子上；数值可溯源，回答里每个数字能不能在证据里找到；安全召回，注入类提问有没有被拦住；还有一项别的项目很少做——自检漏报，即 Agent 自己说通过、而独立复算发现有问题的次数，越接近 0 越好，现在是 0。

**S12　改革沙盘**

> 诊断完之后呢？我们把结论直接接到决策上。这是培养方案改革沙盘：调整课程学时、增删产业模块，五个维度立刻重算——岗位匹配度、能力均衡度、现代工具覆盖、实践学时占比、缺口收敛度。点「一键寻优」，给定学时预算，算法按单位学时增益贪心搜索，岗位匹配度从 47.8 拉到 77.5，右边是前后五维雷达对比，下面是每一步的决策轨迹。

**S13　能力路径**

> 对学校是沙盘，对学生就是路径。选定目标岗位后，算法在知识点共现图和跨课程语义邻接图上跑多源 Dijkstra，找出最短的补强链，再按每学期 96 学时排课。左边是能力就绪度，右边是每一学期该修什么、补哪些知识点、大概多少学时。

**S14–S15　交付与收尾**

> 最后是交付。诊断完不只是出一份报告——报告中心可以按角色生成四种口径，更重要的是这个按钮：导出课程矩阵 CSV，18 列包含课程、知识点、现行学时、改革后学时、缺口判定和调整建议，UTF-8 BOM 编码，Excel 直接打开，教务可以批量导入。
>
> 技术底座上，我们把端和云分开了：向量化、检索、图算法、数值计算全部在本地确定性完成，云端只做语言组织。所以它零 token 能跑、断网能演示、结果可复现。谱合产教——让专业建设从经验判断，变成数据决策。

## 3. 本机渲染（TraceReel）

> ⚠️ [`tracereel-trace.example.json`](./tracereel-trace.example.json) 里的 `x` / `y` 是按 1919×992 视口**估算的占位值**（左侧导航宽约 248px、每项高约 56px）。真正渲染前，请用 Muse 导出的 `agent-output.json` 里的真实坐标覆盖，否则鼠标会落到偏一点的位置。

```bash
npm install -g tracereel
tracereel doctor                       # node≥20 / ffmpeg / Chromium / 磁盘

# 把 Muse 产出的 agent-output.json + shots/ 放好后
tracereel import agent-output.json --adapter muse -o demo.tracereel
tracereel validate demo.tracereel/trace.json --json
tracereel inspect  demo.tracereel/trace.json --json     # 先看镜头规划与时长
tracereel reconstruct demo.tracereel/trace.json -o demo-silent.mp4
tracereel audio demo-silent.mp4 --trace demo.tracereel/trace.json \
  -o demo.mp4 --subtitles both
```

成片参数：H.264 / 1080p60 / AAC 48kHz 立体声 / −16 LUFS / −1.5 dBTP。

## 4. 注意事项

| 项 | 说明 |
|---|---|
| **平台** | TraceReel 官方验证环境是 **Linux**，macOS 与 **Windows 未验证**；建议 WSL 或一台 Linux VPS 渲染 |
| **Muse 地区** | 目前开放美国 / 加拿大，需要对应网络环境 |
| **中文 TTS** | Muse 的 TTS 未必支持中文；不支持就用剪映「文本朗读」生成旁白，再交给 `tracereel audio` |
| **光标双影** | 截图里通常已含系统光标，渲染前需要抹掉，否则成片里会有两个鼠标 |
| **描述口径** | 官方要求只能称 "reconstructed from real screenshots"，**不能说成 live recording** |
| **敏感信息** | 全程不要输入真实账号密码；截图目录按凭据级别保管 |
| **失败兜底** | 若 S08 抽屉或 S11 评测不稳定，直接跳过该镜头，用 S07/S10 的静态截图 + 长旁白顶上（旁白已按可省略设计） |
