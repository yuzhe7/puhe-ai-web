# 魔搭创空间部署 · 逐步操作手册（路径 B）

> 适用版本：v4 · 2026-11-05
> 目标：把 `puhe-ai-web` 发布为公开在线演示，拿到 `https://modelscope.cn/studios/<账号>/<空间名>` 链接，补齐赛道「在线演示加分」。
> 预计：账号准备 10 分钟 + 首次构建 3–5 分钟 + 验收 5 分钟。

---

## 0. 开始前先记住三件事

1. **部署包不要直接拖整个开发目录**：`node_modules`（数百 MB）、`.next`（构建产物）、`docs`、本地 `.env` 都要排除。用 `npm run pack:studio` 生成干净包。
2. **密钥不进仓库**：Token 通过创空间 **Secrets** 注入；仓库里只有 `.env.example` 模板。打包脚本会扫描硬编码凭证，发现即中止。
3. **不配 Token 也能完整演示**：应用会自动回落本地确定性引擎，10 个页面与全部算法照常运行。所以即使部署当天 Token 出问题，演示不会翻车。

**最终产物**：一个公开链接；`/api/status` 返回运行态；`npm run verify:studio -- <链接>` 全部通过。

## 1. 前置条件（逐项打勾）

| # | 条件 | 说明 |
|---|---|---|
| 1 | 魔搭账号 | <https://modelscope.cn> 注册登录 |
| 2 | **绑定阿里云账号 + 实名认证** | API-Inference 的硬性前提（未实名无法调用模型 API）；部分账号在创建空间时也会要求先完成认证，建议提前做完 |

### 两个 Token 别弄混

| 名称 | 用途 | 何时需要 |
|---|---|---|
| `MODELSCOPE_SDK_TOKEN` | **应用运行时**调用魔搭 API-Inference 的模型推理密钥 | 想让 Copilot 出真实大模型回复时需要；不填则离线演示 |
| `MODELSCOPE_API_KEY` / `MODELSCOPE_API_TOKEN` | **平台侧** OpenAPI、Git 推送、配置变量时用的访问令牌 | 仅「Git 推送 / 官方 CLI」方式需要；网页上传不需要 |

两者通常来自同一个「访问令牌」页面，但用途不同，变量名不要写错。

## 2. 生成干净上传包

```bash
cd puhe-ai-web
npm run pack:studio
# 若提示目录已存在：npm run pack:studio -- --force
```

输出目录 `studio-package/`。脚本会做四件事：

1. 只复制运行必需文件（见附录 A）
2. 生成带创空间 YAML 头的 `README.md`：`sdk: docker`、`app_port: 7860`
3. **扫描疑似硬编码密钥**（`ms-…`、`sk-…`、Bearer 明文、赋值型密钥），命中即中止
4. 打印文件清单与体积（正常应为几十个文件、几百 KB 量级，不含 `node_modules` / `.next`）

看到 `✓ 敏感信息扫描通过` 才继续。

| 必须在包里的文件 | 作用 |
|---|---|
| `Dockerfile` | 三阶段构建，监听 `0.0.0.0:7860` |
| `ms_deploy.json` | 告诉平台 `sdk_type: docker`、资源档、端口 |
| `README.md` | 创空间首页说明 + YAML 配置头 |
| `package.json` / `package-lock.json` | `npm ci` 依赖锁定 |
| `next.config.mjs` / `tsconfig.json` / `tailwind.config.ts` / `postcss.config.js` / `.eslintrc.json` / `next-env.d.ts` | 构建配置 |
| `src/` | 全部页面、API、算法与组件 |
| `.dockerignore` / `.env.example` | 构建上下文排除规则 / 环境变量模板 |
| `scripts/check-modelscope.mjs` | 容器内连通性自检（可选） |

> 常见错误：把 `studio-package/` 这一层目录整体拖进文件区，导致仓库根目录多套了一层，平台找不到 `Dockerfile`。**要拖的是目录里面的文件**。

## 3. 本地预验证（强烈建议，5 分钟）

### 方式 A：本机有 Docker（最贴近线上）

```bash

  -e MODELSCOPE_SDK_TOKEN=ms-你的Token \
```


## 4. 创建创空间（先找到正确入口）

> ⚠️ **纠正常见误解：控制台里没有叫「编程式创空间」的按钮。**
> 官方《创空间创建与搭建》文档的原话是：社区提供「**编程式创建**」与「**交互式创建**」两种**创建方式**；
> 其中「编程式创建」下又有「**自定义创建**」与「**快速创建并部署**」两种**模式**，
> 二者**在创建页顶部标题栏切换**。后者官方文档明确标注「当前正在 Beta 测试中」，因此可能没对所有账号开放。
> 本手册早期版本把方式名写成按钮名、把模式名写成「快速部署并创建」，两处均已修正。

### 4.1 按钮到底在哪（任选一个入口）

| 入口 | 位置 | 实际文案 |
|---|---|---|
| **直达链接（最省事）** | 浏览器直接打开 `https://www.modelscope.cn/studios/create` | 直接进入创建页 |
| 头像菜单 | 任意页面**右上角头像** → 下拉菜单 | **「创建创空间」** |
| 创空间首页 | <https://www.modelscope.cn/studios> 页面**顶部** | **「我要创建」** |
| 快捷加号 | 部分版本右上角「+」 | **「创建创空间」** |

> **实测页面核对（2026-11-05，已登录账号）**：创空间首页顶部有一条
> 「**创建空间 → 搭建应用 → 发布空间 → 分享创意**」流程横幅，
> **「我要创建」是这条横幅最右端的紫色描边按钮**，紧挨「分享创意」文字右侧；
> 横幅第 1 步「创建空间」（紫色文件夹图标）本身也是入口。
> 右上角显示头像 + 魔粒数（如 `359`）即代表已登录；若显示「登录 / 注册」，则不会出现创建按钮。
> 注意实际域名带 `www.`：`www.modelscope.cn`。

**三个最常见的「找不到」原因**：

1. **未登录** —— 页面只显示「登录 / 注册」，不会给创建按钮；先登录再刷新。
2. **走错站点** —— 国内站 `modelscope.cn` 与国际站 `modelscope.ai` 账号、令牌、内容**不互通**，本项目按国内站操作。
3. **在找 Beta 模式** —— 「快速创建并部署」不是独立按钮，它在创建页**顶部标题栏**作为与「自定义创建」并列的切换项；灰度未开放时根本不显示。

### 4.2 两条路线（功能等价，选一条即可）

| 路线 | 依赖 Beta | 说明 |
|---|---|---|
| **A. 快速创建并部署** | ✅ 是 | 创建时直接上传整个项目文件夹并触发部署，步骤最少 |
| **B. 自定义创建 + Git 推送** | ❌ 否，**稳定可用** | 先创建空仓库 → 在部署设置里选 Docker SDK → `git push` 代码；还能留下分阶段提交历史，参赛更合适 |

> 若顶部没有「快速创建并部署」切换项、点了没反应、或上传按钮不可用，**直接走路线 B**（见 4.4），不需要等 Beta 权限。

### 4.3 路线 A：网页上传（若 Beta 可用）

| 步 | 操作 | 填写 / 注意 |
|---|---|---|
| 1 | 用 4.1 任一入口进入创建页 | 确认是「编程式创建」方式 |
| 2 | 在**页面顶部标题栏**切到「**快速创建并部署**」 | 别停在默认的「自定义创建」，否则不会在创建时读 `ms_deploy.json` |
| 3 | 填基础信息 | **空间名**：英文小写 + 连字符，如 `puhe-edu-graph`；**描述**：一句话说明是产教融合 AI 诊断平台；**可见性**：建议先 Private，验收通过再改 Public |
| 4 | 选运行环境 | **SDK：Docker**；硬件选免费 `platform/2v-cpu-16g-mem`（2 核 / 16G，本项目够用；xGPU 档需申请且可能产生费用） |
| 5 | 上传文件 | 把 `studio-package/` **内的全部文件**拖入（可全选拖拽）；确认 `Dockerfile`、`ms_deploy.json`、`README.md` 都在仓库**根目录** |
| 6 | 点击 **「确认创建并部署」** | 平台开始构建镜像 |

### 4.4 路线 B：自定义创建 + Git 推送（推荐，不依赖 Beta）

**步骤 ① 展开 · 创建页实测（2026-11-05）**：点「我要创建」后进入的是官方
「编程式创建 → **自定义创建**」的基础信息表单，**这是正确页面，不是走错了**。
页面滚动到下半部可见 `License`（默认 `Apache License 2.0`）、`描述`（上限 2000 字）、
`封面图`（只支持 jpg/png，高度 >220px、宽度 >400px，也可直接选默认图片）、`标签`；
底部是紫色「**创建**」与「取消创建」按钮，右侧有「封面预览」。
往上滚动还有空间英文名称、中文名、所有者、是否公开等字段。

| 字段 | 建议值 |
|---|---|
| 空间英文名称 | `puhe-edu-graph`（小写英文 + 连字符，会进访问链接） |
| 中文名称 / 描述 | 谱合产教 · AI Native 产教融合智能诊断平台；一句话说明双侧三层图谱与三维诊断 |
| 所有者 | 当前登录账号（个人） |
| License | 保持 `Apache License 2.0` |
| 是否公开 | 先选 **Private**，验收通过再改 Public |
| 标签 | 可选，如 `education, knowledge-graph, ai-agent` |
| 封面图 / 默认图片 | 可选，与部署无关 |

> 若**页面顶部标题栏没有「快速创建并部署」切换项**（Beta 未开放），不要继续找按钮：
> 就保持当前「自定义创建」填完并点「创建」，得到一个空仓库，然后按下面的 Git 步骤推送。
> 创建完成后到「设置 / 部署设置」把 SDK 确认为 Docker。

```bash
# ① 网页创建：走 4.1 任一入口 → 保持默认「自定义创建」→ 填名称/可见性 → 创建
#    创建后在「设置 / 部署设置」把 SDK 选为 Docker（ms_deploy.json 里也已声明 sdk_type=docker）

# ② 克隆空仓库（Git 访问令牌从 https://modelscope.cn/my/myaccesstoken 获取）
git clone https://oauth2:<Git访问令牌>@www.modelscope.cn/studios/<账号>/<空间名>.git
cd <空间名>

# ③ 把上传包内容复制进仓库根目录（注意是目录里面的文件）
cp -r /path/to/puhe-ai-web/studio-package/. .

# ④ 提交并推送，默认分支是 master
git add .
git commit -m "feat: initial deployment of puhe AI web"
git push -u origin master
```

推送后平台会自动按 `Dockerfile` 构建；后续迭代就是 `git add -A && git commit && git push`。
若创建页已经能选 SDK，直接选 **Docker** 可省掉第 ① 步里的部署设置操作。
**若创建页的 SDK 下拉里压根没有 Docker**：创建表单确实可能不提供框架选择（2026-11-16 实测就是如此，建出来默认是 Gradio）。此时**不要先 push 也不要先部署**，按下面顺序处理：

1. 先在网页创建空间（默认 Gradio 没关系）
2. **立刻**进「设置 → 部署设置」，把「应用部署框架」改成 **docker**，点 **保存**
3. 确认保存成功后**再** push 代码、再触发部署

> ⚠️ 顺序很重要：如果先部署过一次（Gradio 构建），平台会把 `sdk_version: 6.29.1` 写进该空间的部署配置。之后即使把框架改成 docker，这个版本字段仍会跟着传下去，导致容器启动时报
> `[studio-launcher] config error: unsupported STUDIO_SDK_TYPE: "docker"` 并退出——**这个残留改不掉，只能换新空间**。
> 实测：先创建 → 立刻改 docker → 再 push → 部署，可稳定成功（构建约 4–5 分钟）。
Git 方式需要本机装好 **Git + Git LFS**（官方前置依赖），本项目包体很小，不会触发 LFS 大文件限制。

### `ms_deploy.json` 字段核对

```json
{
  "$schema": "https://modelscope.cn/api/v1/studios/deploy_schema.json",
  "sdk_type": "docker",
  "resource_configuration": "platform/2v-cpu-16g-mem",
  "port": 7860
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `sdk_type` | ✅ | `gradio` / `streamlit` / `docker` / `static`，本项目必须 `docker` |
| `resource_configuration` | ✅ | 免费档 `platform/2v-cpu-16g-mem` |
| `port` | ✅（docker） | **必须 7860** |
| `sdk_version` / `base_image` | 仅 gradio/streamlit | 我们不需要 |
| `environment_variables` | 可选 | **不要在这里写密钥**，改用第 5 步的 Secrets |

## 5. 配置环境变量与密钥

入口：创空间 → **设置 / 空间设置 → 变量与密钥**（Secrets / 明文变量）。

| 变量名 | 类型 | 建议值 | 必需 | 说明 |
|---|---|---|---|---|
| `MODELSCOPE_SDK_TOKEN` | **Secret** | `ms-xxxx` | 否 | 不填 = 本地确定性引擎；这是唯一敏感项 |
| `AI_PROVIDER` | 明文 | `modelscope` | 否 | `Dockerfile` 已内置默认值 |
| `DEMO_MODE` | 明文 | `false` | 否 | 设 `true` 可强制完全离线 |
| `VISION_MODEL` | 明文 | `Qwen/Qwen2.5-VL-72B-Instruct` | 否 | 启用图片 JD 抽取时才填 |
| `AI_MODEL` | 明文 | 具体 Model-Id | 否 | 想换模型时覆盖预设 |

规则提醒：

- **禁止把 Token 硬编码进代码、`ms_deploy.json`、Dockerfile 或 README**；非敏感配置才用明文变量。
- 平台保留 `Authorization`、`X-modelscope-*`、`X-studio-*` 等请求头，不要把应用响应用成这些头（本项目未使用）。应用**出站**调用魔搭模型时带 `Authorization: Bearer` 是协议要求，不属于该限制。
- 改完变量需要**重新部署/重启**才生效。

## 8. ⚠️ 关键风险：URL 挂载路径（务必先验证）

创空间的公开页是 `https://modelscope.cn/studios/<owner>/<repo>`，平台可能给应用**独立入口（根路径）**，也可能用**子路径反向代理**。本项目默认按根路径部署，前端 `fetch('/api/...')` 与 `<Link href="/graph">` 都是绝对路径；若平台是子路径代理，会出现「首页能开、API 全 404、点导航跳到平台根」。

**三步诊断**（部署后立刻做）：

1. 打开浏览器 DevTools → Network，刷新首页，找到 `/api/status` 请求，看**完整 URL** 与状态码。
2. 若 URL 是 `https://modelscope.cn/api/status`（丢了空间前缀）且返回 404 → 子路径挂载。
3. 点侧栏「知识图谱」，若跳到 `https://modelscope.cn/graph` 并 404 → 同样是子路径挂载。

**修复方案 A｜平台给独立入口或根路径代理**：无需改动，直接进入第 9 步。

**修复方案 B｜确认是子路径代理**：在 `next.config.mjs` 的 `nextConfig` 中加两行（把 owner/repo 换成你自己的）：

```js
const studioBase = '/studios/<owner>/<repo>';
const nextConfig = {
  basePath: studioBase,
  assetPrefix: studioBase,
  // ……其余配置保持不变
};
```

然后：

```bash
npm run pack:studio -- --force
npm run build          # 本地确认构建通过
# 重新上传 studio-package 内文件 → 重新部署
```

> `basePath` 是**构建期**配置，只改运行时环境变量无效；必须重新打包并让平台重新构建镜像。
> 不确定时不要提前加：根路径部署加了 `basePath` 反而会把所有链接弄坏。

| 现象 | 先看哪里 | 处理 |
|---|---|---|
| **找不到「编程式创空间」按钮 / 找不到「快速部署并创建」** | 登录状态、站点域名、创建页顶部标题栏 | 本就没有这个按钮：方式叫「编程式创建」，按钮实际是「创建创空间」或「我要创建」，直达 `https://modelscope.cn/studios/create`；模式叫「**快速创建并部署**」，在**顶部标题栏**切换且为 Beta 灰度。未登录不显示按钮；国内站是 `modelscope.cn`。没有 Beta 就走第 4.4 节 Git 路线 |

| 点击导航跳到平台根路径 404 | Network | 同上，`basePath` 同时修好 Link |
| `/api/status` 一直 `mode=local` | Secrets | 变量名拼写 `MODELSCOPE_SDK_TOKEN`；改完要重新部署；用 `npm run check:modelscope` 验证 Token 本身 |
| Copilot 输出错误后降级 | 运行日志 | Token 无效 / 额度用尽 / Model-Id 下线；换模型 ID 或稍后重试；本地引擎兜底已生效 |

| 部署成功但别人打不开 | 空间设置 | 可见性改为 Public |

### 14.2 踩坑与结论（本文档已据此修正）

1. **创建表单可能没有 SDK 选项**，建出来默认 Gradio；`ms_deploy.json` 的 `sdk_type: docker` **不会**自动改变空间的 SDK 类型。
2. **必须先改 SDK 再部署**：先部署过一次 Gradio，平台会把 `sdk_version: 6.29.1` 固定进部署配置，之后改 docker 仍会带着它，容器启动直接退出：
   `[studio-launcher] config error: unsupported STUDIO_SDK_TYPE: "docker"`。该残留无法在网页清理（JSON 配置里也没有这个字段），**只能换新空间**。
3. **改 SDK 只能走网页**：`PATCH/PUT /openapi/v1/studios/{owner}/{repo}`、`/settings`、`/config` 等路径均为 404；只有 `POST .../deploy` 可用。
4. **部署可用 OpenAPI 触发**（Bearer 用访问令牌）：
   ```bash
   curl -X POST -H "Authorization: Bearer ms-xxx" \
     https://www.modelscope.cn/openapi/v1/studios/<owner>/<repo>/deploy -d '{}'
   ```
5. **私有空间无法直接访问**：`.ms.show` 域名会返回
   `403 {"Message":"Unauthorized..."}`；带 `Authorization: Bearer <token>` 也会提示改用
   `https://studio-<owner>-<repo>.api-inference.modelscope.net`（API 专用域名）。
   要让评委直接打开，必须在「设置 → 基础信息 → 是否公开」改为**公开**并保存。
6. **状态查询接口**：`GET https://www.modelscope.cn/api/v1/studio/{owner}/{repo}`（公开空间免登录，私有空间需带令牌），`Status` 取值 `Empty / CreatingBuildingImage / Creating / Running / Failed`。
